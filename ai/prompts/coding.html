1. 接手陌生模块：先读懂再动手 ​

text
背景：接手一个已有项目，技术栈【Spring Boot 2.7 + MyBatis-Plus + MySQL 8】，入口在【XxxApplication】，我要改的模块是【包路径】。
任务：不要改任何代码。先帮我搞清楚这个模块——
1) 对外暴露哪些接口，各自被谁调用；

3) 有哪些隐含约定（事务边界、缓存、异步、幂等）；
4) 哪些地方看着能改、实际不能动（历史包袱）。
输出：先给一份结构说明和调用链，标出你不确定的地方，我来确认。

3. 重构但不改行为 ​

text
背景：这段代码【贴代码】在【类/方法】，现在的问题是【圈复杂度高/重复逻辑/命名混乱/职责不清】。
任务：在不改变外部行为的前提下重构。
约束：方法签名不变；异常类型和错误码不变；日志内容尽量不变；不引入新依赖；一次只做一类改动（先拆方法，再改名，最后抽类）。
输出：分步骤的重构计划 + 每一步的 diff，我逐步确认后再往下。

4. 审自己的 diff（没有同事时最有用） ​

text
背景：这是我刚写的改动，spec 是【贴 spec 或需求描述】，diff 如下【贴 diff】。
任务：只做审查，不要改代码。按这个顺序检查——
1) 是否完整实现了 spec，哪条没实现；

3) 异常是否被吞掉，错误信息是否可定位；

6) 日志是否泄露敏感信息。
输出：按严重程度排序的问题清单，每条给出所在行和修改建议；没问题的项也要明确写“已检查，无问题”。

3. 并发与偶现问题 ​

text
背景：接口【接口名】在高并发下偶发【现象：超卖/重复数据/数据不一致/死锁】。
相关代码：【贴 Service 方法 + 事务注解 + 涉及的 SQL】。
现状：QPS 约【N】，库存/余额类字段更新方式是【先查再改 / 直接 UPDATE / 乐观锁】。
任务：1) 列出所有可能的并发窗口，标出代码行；2) 每个窗口给验证方法（怎么稳定复现）；3) 给修复方案并对比代价（悲观锁/乐观锁/唯一键/队列）。
约束：不改接口；锁定范围尽量小。

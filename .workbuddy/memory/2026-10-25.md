## 推送到 GitHub：网络阻断下的 API 通道方案（2026-10-25 15:15-15:35）
- 用户两次要求 push。常规 `git push` 全部失败：本机 HTTPS 代理（WorkBuddy 沙箱代理，端口每轮变化）对 github.com:443 返回 502/断连，SSH 22 直连虽通但密钥未在 GitHub 注册；**api.github.com 经代理可达（200）**。
- 方案：Node 脚本 `.workbuddy/push-via-api.cjs`（后移至用户级 ~/.workbuddy/）经代理 CONNECT 隧道调 GitHub Git Database API，按拓扑序重放提交（POST /git/blobs → /git/trees 带 base_tree → /git/commits → PATCH /git/refs/heads/main）。令牌从 Git Credential Manager 经 `git credential fill` 取，只走环境变量不打印。
- 结果：3 个提交（59ed09a2/f0191c9b/ea2cdfcc）重放后 SHA 与本地完全一致（blob/tree/commit 均为内容寻址，API 创建即同 SHA），ref 更新成功，`git update-ref refs/remotes/origin/main` 同步追踪引用。
-  GitHub Pages 自动触发构建（status=building），站点 https://gao-shu.github.io/my-vitepress-site/。
- 经验：沙箱代理端口每轮轮换（4717→1592→13822…），脚本改为从 env https_proxy 动态读取；gitblob sha 本地/远端一致可作为正确性校验。

# Go 语言总结

> 我对 Go 的定位：**能读能改、能写小服务**，不是第二主栈。

---

## Go 的核心特点

- 语法少，上手曲线平  
- **Goroutine + Channel**：并发模型直观  
- 编译成单二进制，部署友好  
- 标准库强，很多事不必先找框架  

---

## 并发与性能边界

- 适合网络 IO、worker、代理类服务  
- 不是自动让业务变简单；域复杂时表达力不如 Java 生态省心  
- 错误处理显式：烦，但线上问题少「吞异常」  

---

## 适合什么 / 不适合什么

| 适合 | 不适合（对我而言） |
|------|-------------------|
| 边车、网关、高并发小工具 | 取代 Java 做整套 CRM/ERP |
| 云原生组件、简单 API | 快速 AI 试错（Python 更快） |
| 对内存/部署体积敏感 | 团队不会 Go 却强行全量迁移 |

---

## 我为什么了解 Go

- 读开源、改小服务时用得上  
- 并发与部署思路能反哺 Java 架构讨论  
- 不与 Java 抢主业务，做 **补位技能**

# 适合什么 / 不适合什么

| 适合 | 不适合当第一选择 |
|------|------------------|
| 中后台、CRM / ERP / MES、长期维护的业务 | 一次性脚本、极速出原型 |
| 团队协作、规范、招聘 | 超轻量边车（可考虑 Go） |
| 强事务、复杂领域逻辑 | 纯 CPU 密集算法服务（可拆出去） |
| 洛阳 / 中小远程主叙事 | 为了「多一门语言」硬换栈 |

## 判断

主战场仍是 **能上线、能维护的业务系统**；脚本与 AI 胶水让 Python，靠近端让 Node(TS)。

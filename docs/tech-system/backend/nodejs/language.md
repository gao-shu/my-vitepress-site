# Node(TS) · 语言与运行时总结

> 这里的栈是 **Node.js 运行时 + TypeScript 语言**（不是纯前端 TS）。  
> 重点：**同一套 TS 打通前端与桌面，服务端怎么用才不踩坑。**

---

## 先分清两层

| 层 | 是什么 | 我怎么选 |
|----|--------|----------|
| **语言** | TypeScript（底层仍是 JS） | 后端默认 TS，不靠裸 JS 扛中型服务 |
| **运行时** | Node.js | BFF / 实时 / Electron 本地服务 |

---

## Node 运行时的核心特点

- **事件循环 + 非阻塞 I/O**：适合高连接、等待多的场景  
- **与前端同语言**：BFF、工具链、Electron 配套成本低  
- **单线程执行 JS/TS**：CPU 重活会堵住整进程  

一句话：Node 强在 **等 I/O**，弱在 **算得凶**。

---

## TypeScript 我怎么看（在 Node 上）

- 类型是协作与重构的安全带，动态 JS 写大会痛  
- 编译到 JS 再跑；类型只在开发期，不替代运行时校验  
- 和前端共用类型/工具链时收益最大  

---

## 适合什么 / 不适合什么

| 适合 | 不适合 |
|------|--------|
| BFF、聚合接口、WebSocket | 重 CPU、复杂强事务核心域（优先 Java） |
| Electron 本地服务、前端同构 | 「为了用 Node 而用 Node」重写整套 ERP |
| 实时通知、轻网关 | 无类型纪律的大团队长期协作 |

---

## 我为什么用 Node(TS)

1. 前端 Vue、桌面 Electron 已在栈内，本地服务与 BFF 同语言最省事  
2. 和 Java 分工：Java 管域与库表，Node 管靠近端的聚合与实时  
3. 不为炫技上 Nest 全家桶；场景简单就 Express/Fastify + TS

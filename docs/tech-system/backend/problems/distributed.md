# 后端问题 · 分布式

## 我怎么看「分布式」

分布式不是荣誉称号。  
**拆服务 = 用运维与一致性复杂度，换团队并行与规模。**

中小团队、MES、多数业务中台：我倾向 **轻量单体 + 模块边界清晰**。

## 常见坑

| 现象 | 常见根因 | 处理方向 |
|------|----------|----------|
| 一拆就慢 | 网络调用变多、无超时 | 合并热点；超时与批量 |
| 数据对不齐 | 当本地事务用 | 最终一致；出箱/状态机 |
| 排障困难 | 无链路追踪 | 至少统一 requestId / 日志 |
| 为拆而拆 | 跟风微服务 | 先量痛点再拆 |

## 我的默认策略

- 配置中心、定时任务、缓存可以先「共享组件」，不等于要拆十几微服务  
- 跨服务一致性：业务状态机 + 补偿，优先于上重型分布式事务  
- 真要拆：按业务边界，不按技术时髦

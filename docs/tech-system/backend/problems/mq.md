# 后端问题 · MQ

## 我怎么看消息队列

MQ 解决的是：**异步、解耦、削峰**。  
引入后必然面对：丢失、重复、积压、顺序。

中小业务 **能不用强依赖就不用**；AI 任务、通知、非核心链路更适合。

## 常见坑

| 现象 | 常见根因 | 处理方向 |
|------|----------|----------|
| 消息丢 | 生产者未确认、Broker 落盘策略、消费未 ack | 确认机制；持久化；正确 ack |
| 重复消费 | 至少一次投递 | 业务幂等（唯一键/状态判断） |
| 积压 | 消费慢、故障、流量突增 | 扩容消费者；临时降级；修毒消息 |
| 乱序 | 多分区并发消费 | 单分区键；或状态机容忍乱序 |

## 我的默认策略

1. 先问：同步调用是否够用  
2. 上 MQ 必须设计幂等  
3. 积压要有监控与人工入口

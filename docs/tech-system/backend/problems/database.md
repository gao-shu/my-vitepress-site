# 后端问题 · 数据库

## 我怎么看数据库问题

业务系统里，**数据库往往是真相与瓶颈同时所在。**  
语言换了，SQL 与事务问题几乎同构。

## 常见坑

| 现象 | 常见根因 | 处理方向 |
|------|----------|----------|
| 接口慢 | 无索引、索引失效、回表过多 | EXPLAIN；改写法；补索引 |
| 深分页慢 | `OFFSET` 过大 | 延迟关联 / 寻关键点翻页 |
| 事务死锁 | 加锁顺序不一致、间隙锁 | 统一顺序；缩短事务；必要时降隔离 |
| 数据不一致 | 事务边界错、跨服务当本地事务 | 划清边界；状态机/补偿 |

## 我的默认策略

1. 表设计与索引先想清楚查询路径  
2. 事务只包「必须一起成功」的最小集合  
3. 慢查询有日志，上线前对热点路径看过 EXPLAIN

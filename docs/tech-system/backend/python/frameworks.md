# Python 框架总结

> 语言快，不代表框架随便选。这里只谈 **我会用哪个、为什么。**

---

## FastAPI

- **我最常用**：写 AI/工具类 HTTP 服务  
- 类型注解 → 自动校验与文档，和「对外契约」很搭  
- async 适合等模型、等下游  

**适合：** 内部 API、模型代理、给 Java 调用的胶水层。

---

## Flask

- 轻、灵活、历史包袱项目多  
- 适合非常小的脚本服务或遗留维护  

**判断：** 新项目我更愿意直接 FastAPI；维护老 Flask 再学够用即可。

---

## Django

- 「电池全」：Admin、ORM、用户体系齐全  
- 适合要快速出带后台的完整站点  

**判断：** 我的主业务已在 Java；Django 不是默认选项。只有「独立小站 + 强 Admin」才考虑。

---

## 我的选择

| 场景 | 选择 |
|------|------|
| AI / 自动化 API | **FastAPI** |
| 几行脚本 + 临时 HTTP | Flask 或甚至不写框架 |
| 完整 Python 业务站 | Django（少见） |
| 任务队列 | 先 Redis 列表/简单 worker；复杂再上 Celery |

**原则：** Python 框架服务于「快」和「旁路」；核心交易与权限仍放 Java。

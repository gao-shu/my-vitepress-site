# Python 语言总结

> 目标不是成为 Python 工程师，而是：**我会用 Python 加速 AI 与自动化。**

---

## Python 的核心特点（在我眼里）

- **表达密度高**：同样逻辑代码更短，适合试错  
- **胶水语言**：擅长把 API、文件、模型、脚本粘在一起  
- **生态偏数据/AI**：调用模型、处理文本与文件很顺手  
- **动态类型**：快，也容易在边界上埋坑（要用注解和校验补）  

---

## 动态类型与开发效率

- 好处：改得快、脚本多、原型一天能出  
- 风险：重构胆怯、线上类型相关 Bug 更隐蔽  

**我的做法：** 对外 API 用 FastAPI + Pydantic；对内脚本保持短小，重要路径加类型注解。

---

## asyncio / 多进程

- I/O 等待（调模型、HTTP）→ `async` 有意义  
- CPU 密集 → 别指望多线程算力（GIL）；用多进程或丢给别的服务  
- 和 Java 比：Python 更适合「旁路服务」，不适合硬扛所有核心域逻辑  

---

## Python 性能边界

- 默认解释执行，绝对性能通常弱于 Java/Go  
- 真正瓶颈常在：**模型延迟、网络、错误重试策略**，不在语言本身  
- 需要吞吐时：水平扩多实例，或把热点迁走  

**判断：** 性能不够先看架构，再怨语言。

---

## Python 适合什么 / 不适合什么

| 适合 | 不适合 |
|------|--------|
| AI API 封装、批处理、运维脚本 | 超大单体复杂中台的第一选择 |
| 快速内部工具 | 强规范、强类型的超大协作域（可仍用 Java） |
| 与 Java/Node 协作的专项服务 | 已有稳定 Java 域还强行重写 |

---

## 我为什么用 Python 做 AI / 自动化

1. 模型与工具 SDK 往往 Python 最全、示例最多  
2. 能快速验证 Prompt / 流程，再决定是否迁回 Java  
3. 和主栈分工清晰：**Java 管业务与状态，Python 管模型与脚本**

# ERP 核心问题清单

> **一句话定位**：ERP 管的是"该做什么、值多少钱"——把订单变成计划，把计划变成单据，把单据变成钱。
>
> **本文用途**：把 ERP 最容易崩的 10 个环节列清楚，每个给出成因、解法与面试口径。配套：[WMS](/scenarios/enterprise-digital/wms) · [MES](/scenarios/enterprise-digital/mes) · [IIoT](/scenarios/enterprise-digital/iiot)。

## 一、ERP 到底在算什么

三件事，按顺序：

1. **算需求**：客户要什么、要多少、什么时候要 → MRP 展开成采购与生产计划。
2. **算执行**：单据流驱动采购、生产、库存、销售 → 每一笔都有凭证。
3. **算钱**：材料 + 人工 + 制造费用 → 成本 → 应收应付 → 总账。

主链路：

```text
销售订单 → MRP 运算 → 采购申请 ──► 采购订单 → 到货 → 入库 → 应付
                    └► 生产工单 → 领料 → 完工入库 → 成本核算 → 总账
销售订单 → 发货 → 出库 → 应收 → 收款 → 应收核销
```

## 二、核心问题清单

| # | 核心问题 | 为什么难 | 典型后果 |
|---|---|---|---|
| 1 | **MRP 运算跑不准、跑不动** | 多层 BOM 递归展开 + 库存/在途/在制 + 批量与提前期策略 | 计划员不信系统，回去手工排 |
| 2 | **BOM 变更失控** | 工程变更要管版本、生效日期、已下达单据 | 车间按旧版 BOM 领料，缺料或报废 |
| 3 | **成本算不准** | 标准与实际两套账、费用分摊口径、期末在制 | 毛利失真，报价拍脑袋 |
| 4 | **账实不符** | ERP 账 vs WMS 实物，双份库存 | 盘点差异巨大，财务不敢结账 |
| 5 | **单据能不能改** | 已审核 / 已被下游引用的单据追溯性 | 改一张单，后面十张单全错 |
| 6 | **期间关账与反关账** | 月结后历史数据冻结，跨期调整无出口 | 关账后还在补单，成本月月重算 |
| 7 | **多组织多工厂内部交易** | 法人账 vs 业务账，内部购销与调拨 | 集团合并报表对不上 |
| 8 | **委外加工** | 发料、耗用、损耗、副产物、加工费 | 委外库存成了黑洞 |
| 9 | **价格与信用管控** | 价格政策、折扣、信用额度占用与释放 | 超信用发货，坏账 |
| 10 | **主数据一致性** | 物料/供应商/客户/单位/汇率 | 一物多码，报表合并失败 |

## 三、五个深水区逐个拆

### 1. MRP 运算：最经典的"算不准"

**问题本质**：MRP 不是一句 SQL 能算完的，它是**按时间分桶的多层净需求推演**。

单个物料的净需求公式：

```text
净需求 = 毛需求 + 安全库存 − 现有库存 − 在途(已下达未到货) − 在制(已下达未完工)
```

毛需求又分两类：独立需求（销售订单、预测）和相关需求（上层物料展开下来的）。

**第一个坑：同一物料重复展开**。物料 A 既在 BOM 第 2 层、又在第 4 层出现，如果按层级逐层展开，A 的库存会被扣两次，计划量偏小 → 缺料。

标准解法是**低层码（Low Level Code, LLC）**：取该物料在 BOM 中出现的最深层级作为低层码，按低层码升序逐层展开，每个物料的净需求只算一次。

```text
物料 A 出现在 L2 和 L4 → LLC(A) = 4
展开顺序：LLC=0 → LLC=1 → ... → LLC=4（A 在最后一次统一结算）
```

**第二个坑：性能**。十万级 BOM、几万个物料、按天分桶、滚动 90 天，递归 SQL 直接超时。

工程解法三步：

1. **BOM 一次性拉到内存建树**（物化路径或父子表 + 缓存），避免数据库递归。
2. **按低层码分轮次批量计算**，每轮只算当前层的物料，层内可并行。
3. **运算任务异步化**：提交任务 → 落 `mrp_run` 主表（running/success/failed）→ 分批写入建议表 → 前端轮询进度。失败可**按物料重跑**，不重跑全量。

**第三个坑：重跑幂等**。同一次运算重复触发，建议单不能翻倍。用 `run_id + 物料 + 需求日期` 做唯一键，重复即覆盖。

> **面试口径**：MRP 的技术难点不在公式，在两点——一是用低层码避免同一物料被重复扣库存，二是把"一次跑几小时"拆成"分批可重跑"。计划员不信系统，90% 是因为跑一次太久、结果又没法解释，所以建议单必须能下钻到"这个需求来自哪张订单、扣了哪些库存"。

### 2. BOM 变更：一张图纸改动，牵出十张单

**问题**：ECN（工程变更）下来要换料，但已经下达的工单、已经采购的订单、已经在线的半成品怎么办？

**解法**：BOM 用**版本 + 生效日期 + 生效状态**三重控制。

- 变更不覆盖原记录，新增一条版本，`effect_date` 生效。
- 已下达单据**锁定 BOM 版本**（下单时快照 `bom_version`），不跟随变更漂移。
- 尚未开工的工单允许"重新展开"，按新版本重算需求并生成变更单。
- 旧料用**替代料**（替代组 + 优先级 + 替代比例）消化，而不是直接删行。

> **面试口径**：BOM 变更的核心不是"改数据"，是"决定谁跟着变、谁不变"。原则是已发生的不追溯、未发生的可重算，中间用替代料做缓冲。

### 3. 成本核算：为什么毛利总是对不上

**两套账要分清**：

| 口径 | 用途 | 特点 |
|---|---|---|
| 标准成本 | 报价、预算、差异分析 | 年初定，全年不变，稳定 |
| 实际成本 | 财务核算、存货计价 | 月末结算，随实际发生波动 |

**差异分析（标准成本法必考）**：

```text
材料价差 = (实际单价 − 标准单价) × 实际用量     ← 采购部门负责
材料量差 = (实际用量 − 标准用量) × 标准单价     ← 生产部门负责
```

**期未在制（WIP）怎么处理**：本月投入的材料 + 人工 + 费用，要在"完工入库"和"期末在制"之间分摊。常用约当产量法或按标准成本留存，剩余进完工。这里口径一旦变，毛利就跳。

**存货计价**：移动加权平均（实时、单据级）、月加权平均（月末一次）、先进先出（批次）。ERP 里改计价方式等于重算历史，实施期就必须定死。

> **面试口径**：成本不准，九成不是算法错，是三个地方漏了——领料没有按工单实际发（用了倒冲但没回写损耗）、制造费用分摊口径每月变、期末在制没留。技术人常忽略的是：成本是**算出来的结果**，源头在 WMS 的领料和 MES 的报工，那两个不准，ERP 怎么算都是错的。

### 4. 账实不符：ERP 和 WMS 打起来了

**问题**：两个系统都有库存，谁准？集成后经常出现"ERP 显示有货，仓库找不到"。

**解法**：明确**实物权威源**与**账面权威源**，并且只保留一个可写入方。

| 事项 | 权威方 | 另一方 |
|---|---|---|
| 实物数量、库位、批次 | WMS | ERP 只读 |
| 存货金额、成本、账务 | ERP | WMS 不参与 |
| 库存调整 | WMS 发起调账单，ERP 审核入账 | 双向留痕 |

配套两个机制：

- **实时回写 + 每日对账**：回写走消息（可靠投递 + 消费幂等），对账跑定时任务比对 `物料 + 仓库 + 批次` 三元组的数量，差异进异常池。
- **不允许双写**：ERP 后台不开放"库存直接修改"功能，所有变动必须有来源单据。

> **面试口径**：账实不符的技术根因通常有三个——回写消息丢了没人发现、同一个物料两边都能改、单位换算丢精度。所以要有对账任务兜底，且数量字段统一用整数存最小单位（如"件"存到 0.001 用整数放大 1000 倍），不要用 float。

### 5. 单据能不能改：追溯性的底线

**规则**：

- 草稿态可改可删。
- 已审核未引用：可反审核（需权限 + 留痕）。
- 已被下游引用：**禁止反审核**，只能红冲（生成负数单据）+ 重开。
- 已关账期间：任何单据不可新增、不可修改，只能在下期做调整单。

**实现要点**：

```text
凭证不可变（immutable）：单据审核后生成快照 JSON 存 detail_snapshot
红冲关系：red_offset_id 指向原单，原单标记 reversed
所有操作写 oper_log：谁、何时、改了什么字段、改前改后
```

> **面试口径**：财务类系统的第一条铁律是"已发生的事实不能删，只能冲"。技术上就是 insert-only + 状态标记，永不物理删除。这条守住，审计就过得去。

## 四、面试高频追问

**Q1：MRP 为什么不能实时算？**
A：实时算意味着每次订单变更都触发全量展开，成本不可接受。工程上是"定时跑 + 关键事件触发局部重算"，比如新增大额订单只重算受影响物料的子树。计划是准实时，不是实时。

**Q2：MRP 结果的准确性怎么保证？**
A：三件事——库存和在手单据要实时（至少准实时）、BOM 要准确且版本一致、参数（提前期、批量、安全库存）要有人维护。技术上再加一层：建议单支持"穿透查看"，能点开看到需求来源和扣减明细，计划员才敢用。

**Q3：并发下两个人同时跑 MRP 会怎样？**
A：用分布式锁 + run 状态表双重控制。同一时刻只允许一个 running，第二次提交直接返回"运算中"，或者按物料分区加锁允许多实例并行算不同分区。

**Q4：多组织架构怎么设计？**
A：三层——法人（Legal Entity）管账、组织（Org）管业务归属、库存组织（Inventory Org）管实物。单据带 `org_id`，权限按组织隔离。内部交易生成双向单据（一方销售一方采购），价格用内部结算价，合并报表时抵消。

**Q5：金额用什么类型？**
A：`BigDecimal`，数据库 `DECIMAL(18,4)`~`DECIMAL(18,6)`，统一舍入模式 `HALF_UP`，中间计算不四舍五入、只在落库和展示时舍入。绝对不用 `double`。

**Q6：ERP 和 WMS 的数据同步用同步接口还是消息？**
A：写入类用消息（异步、可重试、削峰），查询类用同步接口（要实时结果）。但"库存是否足够"这种校验不能只信异步，要么查 WMS 的实时接口，要么在 ERP 侧维护一份可用的预占量。

**Q7：怎么处理"先发货后开票"的暂估？**
A：发货出库时按标准成本或最近采购价做暂估应付，发票到达后做三单匹配（采购单 / 收货单 / 发票），差异走价格差异科目，冲回暂估。

## 五、30 秒速答卡

> ERP 我理解是三层：上面是计划层，MRP 按低层码展开多层 BOM，算出净需求，难点是同一物料不能重复扣库存、以及大 BOM 要分批可重跑；中间是执行层，靠单据流驱动采购生产库存，关键是"已发生不可删只能冲"和期间关账；下面是财务层，标准成本和实际成本两套账，差异拆价差量差，成本准不准取决于 WMS 领料和 MES 报工的数据质量。跨系统上，实物以 WMS 为准、账面以 ERP 为准，靠消息回写加每日对账保证一致。

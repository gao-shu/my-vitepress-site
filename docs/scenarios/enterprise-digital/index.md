# 企业数字化：四大系统边界与问题全景

> **一句话定位**：企业数字化不是"上四套系统"，而是让同一个物料在 ERP、WMS、MES、IIoT 里始终只有**一个真相**——该做什么、做得怎样、东西在哪、设备在干什么。
>
> **本文用途**：面试前 20 分钟速览。先分清四层边界，再按清单逐条自查。四篇分册见 [ERP](/scenarios/enterprise-digital/erp) · [WMS](/scenarios/enterprise-digital/wms) · [MES](/scenarios/enterprise-digital/mes) · [IIoT](/scenarios/enterprise-digital/iiot)。

## 一、四层边界：四个判据分清归属

面试被问"ERP 和 MES 什么区别"，不要背定义，直接给判据。

| 判据 | 归属 | 说明 |
|---|---|---|
| 要不要**记账**、算钱 | ERP | 订单、应收应付、成本、总账 |
| 要不要**动位置** | WMS | 库位、容器、上下架、拣货路径 |
| 要不要管**工序和人** | MES | 工单、工序流转、报工、质检 |
| 要不要**直连设备** | IIoT | 协议、点位、采集、设备状态 |

四层各自的时间粒度也是天然的划分依据：

| 层 | 回答的问题 | 管理对象 | 时间粒度 | 典型角色 |
|---|---|---|---|---|
| ERP | 该做什么、值多少钱 | 订单 / 物料 / 资金 | 天 · 周 · 月 | 计划员、财务 |
| MES | 现在做得怎么样 | 工单 / 工序 / 人机料法环 | 分钟 · 小时 | 车间主管、班组长 |
| WMS | 东西在哪、怎么动 | 库位 / 批次 / 容器 | 秒 · 分钟 | 仓管、拣货员 |
| IIoT | 设备在干什么 | 点位 / 设备 / 状态 | 毫秒 · 秒 | 设备工程师 |

> **面试口径**：ERP 是"账本"，WMS 是"地图"，MES 是"工位看板"，IIoT 是"神经末梢"。四者不是替代关系，是四个时间尺度上的同一件事。

## 二、主链路：一条线串起四个系统

```text
客户订单
   │  ERP：销售订单 → MRP 运算 → 采购申请 / 生产工单
   ├──────────────────────────────┬──────────────────────┐
   ▼                              ▼                      ▼
采购到货                        生产工单                设备侧
   │                              │                      │
   ▼                              ▼                      ▼
WMS：收货 → 质检 → 上架      MES：派工 → 报工 → 质检   IIoT：采集产量/状态/参数
   │                              │                      │
   └──────────► 库存 ────────────┘                      │
                  │                                     │
                  ▼                                     │
            WMS：波次拣货 → 复核 → 发运                  │
                  │                                     │
                  ▼                                     │
            ERP：应收 / 应付 → 成本核算 → 总账  ◄────────┘
                                        （实际产量、能耗、工时回写）
```

链路里有两个容易讲错的地方，面试常用来区分"用过系统"和"懂系统"：

1. **成品入库谁发起**：MES 完工报工发起入库申请，WMS 执行实物上架，ERP 只接收"库存增加"的账务结果——三件事、三个系统、三种语义。
2. **实际成本从哪来**：材料成本来自 WMS 的实际领料（不是 BOM 标准用量），人工与制造费用来自 MES 的报工工时和设备运行数据，ERP 只做归集与分摊。

## 三、跨系统的四道坎

这四道坎是所有工业软件项目的公共难点，也是面试里"能不能做架构"的试金石。

### 坎 1：主数据不统一

**问题**：同一个物料，ERP 叫 `M-001`，MES 叫 `物料A`，WMS 叫 `SKU0001`；单位一个用"个"一个用"箱"。集成一上线，第一条数据就错。

**解法**：确立**主数据单一权威源**（通常是 ERP 或独立 MDM），其余系统只做映射不做新增。物料编码全局唯一、单位建换算表、工厂/仓库/库位统一编码规则。接口传输时**只传编码不传名称**。

**面试口径**：集成的第一件事不是写接口，是坐下来定编码规则。主数据没统一，接口写得再漂亮都是在同步错误。

### 坎 2：库存谁是唯一真相

**问题**：ERP 有库存、WMS 也有库存，两边差 37 件，谁的准？谁也不认。

**解法**：**实物以 WMS 为准，账面以 ERP 为准**，WMS 每次库存变动实时（或准实时）推送 ERP；ERP 不允许手工改库存，只能通过单据调整；每日做库存对账任务，差异进异常池人工处理。

**面试口径**：一个物料在一个时点只能有一个权威库存。两个系统都能改库存，等于没有库存。

### 坎 3：单据状态对不齐

**问题**：ERP 里工单已"完工"，MES 里还在"生产中"；ERP 已"关闭"，WMS 还有未清的领料单。

**解法**：定义**跨系统状态映射表**，只允许单向驱动（下游不能反向改上游终态）；每个单据带全局唯一业务号和版本号；状态回写走事件而非轮询。

**面试口径**：状态机对齐的关键是"谁有权推进状态"写清楚。多个系统都能推同一个状态，必然打架。

### 坎 4：一致性只有最终一致

**问题**：ERP 扣了库存，WMS 上架失败，中间件超时，数据悬空。

**解法**：本地事务 + 消息表（Transactional Outbox）+ 消费端幂等 + 定时对账兜底。不做跨系统强一致，做**可补偿的最终一致**：每笔跨系统操作留"业务流水 + 状态 + 重试次数"，卡住就告警。

**面试口径**：跨系统不要谈分布式事务，谈"本地消息表 + 幂等 + 对账"。前两个保证不丢不重，第三个保证错了能发现。

## 四、四套系统的核心问题索引

| 系统 | 核心命题 | 最硬的三个问题 | 分册 |
|---|---|---|---|
| ERP | 计划准不准、成本算不算得清 | MRP 运算、BOM 变更、成本核算 | [ERP 核心问题](/scenarios/enterprise-digital/erp) |
| WMS | 库存准不准、作业快不快 | 库存准确性、波次拣货、批次效期 | [WMS 核心问题](/scenarios/enterprise-digital/wms) |

## 五、60 秒自测：能不能讲清一条链路

面试官问"你做过库存，讲一下从采购到入库怎么走"，合格的回答应该包含**四层各一句**：

> 采购单在 ERP 下达并审核，生成到货通知推给 WMS；WMS 按 ASN 预约月台收货，扫批次号入库到质检区，质检合格后按上架策略分配库位，实物上架同时把"库存增加"回写 ERP；ERP 收到回写后更新账面库存和暂估应付，等发票到了做三单匹配生成应付。整个链路里 WMS 管实物位置和批次，ERP 管账和钱，中间用业务单号做幂等，每天跑一次库存对账兜底。

这段话里藏了 6 个技术点：主数据、状态映射、幂等键、实物与账面分离、暂估应付、对账补偿。能把它们逐个展开，追问就接得住了。

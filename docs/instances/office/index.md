# 04 办公自动化

> OA、BPM、表单与数据收集 —— 办公协同类系统（审批 / 公告 / 流程 / 收集）。与「企业业务应用」按场景分工：本模块聚焦办公协同，企业业务应用聚焦经营业务数据；二者共用 OpenBiz 底座（多租户 / 权限 / 状态机 / 动态表单），技术实践页会有交叉引用。

**项目状态图例**：✅ 已验证 · 🔧 验证中/在建 · 📋 规划中（尚未开始实现）

## 项目规划

| 序号 | 软件项目 | 核心功能 | 状态 |
|---|---|---|---|
| 1 | [OA 办公自动化系统](/instances/office/oa) | 待办事项、通知公告、办公申请、审批中心 | 📋 规划中 |
| 2 | [BPM 业务流程管理系统](/instances/office/bpm) | 流程设计、审批规则、条件分支、流程执行 | 📋 规划中 |
| 3 | [在线表单与数据收集系统](/instances/office/form) | 表单设计、字段配置、数据提交、数据统计 | 📋 规划中 |

## 与现有内容的关系

- 本模块暂无代码载体，但实践经验完整：飞书机器人、审批待办自动化、消息 Webhook、日报生成的踩坑与方法已沉淀在[功能开发 › 办公自动化](/apps/office/)
- 三者共享同一底座能力（审批流、消息通知、权限），建议作为一个组合规划，避免三个独立空壳；其中 **BPM 是核心**，OA 的审批中心与表单系统的数据入口都可复用它

## 优先级建议

1. **在线表单与数据收集系统**（字段配置 + 数据统计链路最短，适合快速闭环）
2. **BPM 业务流程管理系统**（流程设计器 + 规则引擎，技术展示度最高）
3. **OA 办公自动化系统**（在 BPM 之上组装待办、公告与申请，最后做集成）

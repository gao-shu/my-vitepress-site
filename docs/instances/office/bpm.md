# BPM 业务流程管理系统

> ✅ 已验证（OpenBiz 最小闭环跑通） · 所属模块：[04 办公自动化](/instances/office/) · 模块优先级：第 2 位 · [查看实证 ↗](/apps/openbiz/bpm)

## 📌 项目简介

BPM（Business Process Management）是办公自动化模块的**核心流程底座**。它提供流程定义、审批规则、条件分支与流程执行能力，让「任意业务对象 + 状态流转」都能用同一套引擎驱动。

- **定位**：本模块的技术核心。OA 的审批中心、表单系统的数据入口都可复用它；同时它也是「企业业务应用」（CRM 商机、ERP 单据、PMS 任务）审批流的统一同构底座——这些系统的状态机 / 流程引擎均以本页描述为准，避免重复表述。
- **核心价值**：把「谁审批、按什么规则、走什么分支、超时怎么办」从业务代码里抽离出来，变成可配置、可观测的流程资产。

## 🗺️ 功能规划

### ✅ 已实现（基于 OpenBiz 试水实证）

| 功能 | 说明 |
|---|---|
| 流程定义 | 节点 / 连线 / 表单绑定（流程定义 + 实例双状态机） |
| 流程实例流转 | 流程实例流转、任务处理、执行轨迹回溯 |
| 审批规则 | 审批人策略（角色 / 上级 / 自由指定） |
| 会签 / 或签 | 多审批人节点的会签与或签 |

### 📋 规划 / 待做

- [ ] 可视化流程设计器（拖拽式节点 / 连线编排）
- [ ] 条件分支网关、超时自动提醒与自动转交
- [ ] 规则引擎增强（动态表达式、审批人计算策略）
- [ ] 流程监控大盘（在途实例、耗时、瓶颈节点）
- [ ] 对外统一状态机 API，供 CRM / ERP / PMS 复用
- [ ] 与工单系统状态机打通（节点流转模型同构）

## 🏗️ 技术架构

### 平台 + 垂直定位

```
┌ 垂直应用层（薄：领域模型 + 表单/流程配置）
│   CRM · ERP · PMS · OA · BPM · Form        ◀ 本页：BPM
├ 平台内核 · OpenBiz（一次建深，覆盖通用能力约 80%）
│   多租户/数据隔离 · RBAC/行级权限 · 工作流引擎 · 动态表单引擎
│   审计日志 · 消息通知中心 · 导入导出/报表 · 开放 API/SSO
└ 数据层 · MySQL 8 · Redis · 对象存储 · 消息队列
```

BPM 是**流程能力所在层**：提供流程定义 / 实例与规则，其余（多租户、权限、消息）复用平台内核。

### 本模块内部结构

```
┌──────────────────────────────────────────────────┐
│                  调用方                              │
│   OA 审批中心 │ 表单系统 │ CRM/ERP/PMS 业务对象       │
├──────────────────────────────────────────────────┤
│               BPM 流程引擎                          │
│  ┌─────────┐  ┌──────────┐  ┌────────────────┐    │
│  │ 定义管理 │  │ 实例运行  │  │ 规则 / 分支引擎 │    │
│  └─────────┘  └──────────┘  └────────────────┘    │
│         │                │                          │
│         ▼                ▼                          │
│   流程定义表        任务实例表（并发任务处理）          │
├──────────────────────────────────────────────────┤
│   OpenBiz 底座：多租户 / 权限 / 状态机 / 动态表单     │
├──────────────────────────────────────────────────┤
│              数据层  (MySQL 8)                       │
└──────────────────────────────────────────────────┘
```

- **核心数据模型**：流程定义 / 节点 / 连线 / 流程实例 / 任务实例。重点是**实例状态机**与**并发任务处理**。
- BPM 不直接面向终端用户，而是被 OA、表单、业务系统「调用」。

# Redis

Redis 是一个基于内存的高性能键值数据库。除了 String、Hash、List、Set、ZSet 等基础数据结构，还提供过期、持久化、发布订阅、Stream、Lua、事务等能力。

实际项目中我主要把它用于：**缓存、分布式锁、计数、限流以及临时状态管理**。本模块按「原理 → 结构 → 场景能力 → 实战」组织，每块强调**怎么用、踩什么坑、怎么优化**，而不是背命令大全。

## 我怎么定位 Redis

```text
不是「第二个 MySQL」
而是：热数据与协调能力层

优先：
  缓存读路径
  分布式互斥（锁）
  计数 / 限流 / 会话与临时状态

谨慎：
  当唯一可靠消息队列（复杂投递语义优先 MQ）
  当永久主存（要靠持久化 + 备份 + 恢复演练）
```

## 核心优化原则（贯穿全模块）

1. **Key 设计规范**：业务前缀 + 明确过期；禁止无 TTL 的大杂烩  
2. **防穿透 / 击穿 / 雪崩**：空值、互斥、过期随机、多级缓存  
3. **锁必须可续期、可校验持有者**：优先 Redisson，忌裸 `SETNX` 忘记过期  
4. **大 Key / 热 Key 单独治理**：拆分、本地缓存、读写分离或集群槽位感知  
5. **批量用 Pipeline / Lua**：减 RTT；耗时命令与 `KEYS *` 禁止上生产  
6. **高可用按需求选型**：主从够用就别上 Cluster；Cluster 要懂槽位与跨槽限制  

按左侧菜单分区推进；实战页把能力串成可口述的项目故事。

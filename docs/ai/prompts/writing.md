# 写作与表达提示词（12 条）

> 写周报、文档、消息时用的 12 条。第一约束永远是读者是谁。
> 通用骨架：背景 → 现状 → 目标 → 约束 → 输出格式，见 [提示词库总览](/ai/prompts/)。

## 模板

### 1. 周报（有事实流水，不写空话）

```text
背景：我是【岗位】，本周在做【项目/模块】。
本周事实（流水，不用组织语言）：
- 【周一：修了 X 问题，原因是 Y】
- 【周二：和 Z 对齐了 W，结论是……】
- 【周三：完成 A 功能，进度 70%】
任务：整理成周报，结构为——本周完成（逐条，带结果和数字）/ 进行中（进度 + 预计完成时间）/ 风险与阻塞（需要谁协调什么）/ 下周计划。
要求：不写“取得阶段性成果”“持续推进”这类词；每条控制在一句话；事实不足的地方标【待补】，不要自己编。
```

### 2. 技术方案文档

```text
背景：要写的方案是【一句话】，读者是【技术负责人 / 跨部门同事】，决策场景是【评审会 / 存档】。
事实：现状【…】，候选方案【A/B】，约束【工期、人力、兼容性】。
任务：写成方案文档，结构——背景与问题 / 目标与非目标 / 方案对比（表格，维度自定但要说清为什么是这几个维度）/ 推荐方案与理由 / 风险与兜底 / 实施步骤与里程碑。
要求：结论放最前面；每个方案都要写“不选它的原因”；不确定的地方标出，不要用模糊表述掩盖。
```

### 3. 会议纪要

```text
背景：这是【会议主题】的原始记录（可能有错别字、口语、重复），参会人【名单】。
原文：【贴记录】
任务：输出三段——结论（已定的，一条一句）/ 待办（谁、做什么、什么时候）/ 争议点（没定下来的，各自立场）。
要求：不写感想和评价；原文没提到的不要补；有歧义的地方保留原话并标【待确认】。
```

### 4. 找人帮忙 / 跨部门沟通

```text
背景：我要找【对方角色】协调【什么事】，我们之间的关系是【同事/上下游/外部】。
事实：需要他做【具体动作】，因为【原因】，卡在我这里的点是【…】。
任务：写一条不超过 150 字的消息，包含：背景一句、需要对方做什么（明确到动作）、时间要求、我能提供什么。
要求：不要铺垫和客套；不要用“麻烦看下”“有空的时候”这类无期限表述；给出两个版本（微信口气 / 邮件口气）。
```

### 5. 技术文章（公众号 / 掘金 / 博客）

```text
背景：我要写一篇关于【主题】的文章，读者是【初级/中级/面试者】，发布在【平台】。
我的真实素材：【踩过的坑、对比数据、代码片段、结论】。
任务：给文章结构 + 开头三段，先不要写全文。
要求：开头用一个具体场景切入，不要“随着 XX 的发展”；每一节都要有可验证的细节（版本号、报错、数据）；结论要能被人反驳，不要写成正确的废话。
```

### 6. 一稿多发（同内容改平台）

```text
背景：原文如下【贴全文】，目标平台：【公众号 / 掘金 / 小红书 / 知乎】。
任务：按平台特性改写，保持事实和结论不变，只调结构、长度、语气：
- 公众号：完整叙事，有小标题，2000 字左右；
- 掘金：技术密度高，代码和结论前置；
- 小红书：短句、分点、口语化，500 字内；
- 知乎：先给结论再论证，适合被引用。
输出：四个版本分开给，不要解释改写逻辑。
```

### 7. 标题十选

```text
背景：文章主题【…】，核心结论【…】，读者最痛的点是【…】。
任务：给 10 个标题，分三类——信息型（说清是什么）、痛点型（戳中问题）、反常识型（制造好奇）。
要求：每个不超过 20 字；不用“震惊”“必看”这类词；标注每个标题适合哪个平台；最后推荐 1 个并说明理由。
```

### 8. 对外通知 / 公告

```text
背景：要通知的对象是【用户/客户/内部同事】，事情是【上线/停机/变更/故障】，影响范围【…】，时间【…】。
任务：写一则通知，结构——发生了什么 / 影响谁 / 什么时候 / 需要对方做什么 / 找谁求助。
要求：不含技术黑话；不用“给您带来不便敬请谅解”这种模板句代替具体说明；故障类要写清当前状态和下次更新时间。
```

### 9. 简历 bullet（结果导向）

```text
背景：这是我的项目事实：【项目名、我做了什么、用了什么技术、结果数据】。
任务：改写成 3~4 条简历 bullet，每条结构为“动作 + 方法 + 结果（带数字）”。
要求：动词开头；不写“负责”“参与”这种弱动词；不写职责描述，只写成果；技术名词保留英文原名；每条不超过两行。
```

### 10. 汇报 / PPT 大纲

```text
背景：要给【听众】汇报【主题】，时长【N】分钟，他们要做的决策是【…】。
任务：给 PPT 大纲，每页一行标题 + 三个要点，控制在【N】页内。
要求：第一页就是结论；每页只讲一件事；数据页要标明来源和口径；最后一页是“需要你决定什么”，不要写“谢谢聆听”。
```

### 11. 翻译与本地化

```text
背景：把下面的【英文/中文】内容翻成【目标语言】，读者是【技术/非技术】，用途是【文档/产品界面/对外发布】。
术语表：【原文 → 译法】。
原文：【贴内容】
要求：术语严格按术语表；界面文案要短，优先动词；技术文档保留代码和命令原文；不要意译成“翻译腔”，翻完读一遍确认像人话。
```

### 12. 校对润色（保原意）

```text
背景：下面的文字是我自己写的，可能有病句、重复、逻辑跳跃，但观点是我的。
原文：【贴内容】
任务：只做三件事——改病句和标点、删重复和废话、调整段落顺序让逻辑连贯。
约束：不改变观点和事实；不替换我的用词习惯（除非确实错）；不增加新内容。
输出：修改后的全文 + 一份“改了什么、为什么”的清单。
```

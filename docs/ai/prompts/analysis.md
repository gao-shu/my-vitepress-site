# 分析与决策提示词（10 条）

> 做对比、定方案、看数据时用的 10 条。维度必须由我给，权重必须由我给。
> 通用骨架：背景 → 现状 → 目标 → 约束 → 输出格式，见 [提示词库总览](/ai/prompts/)。

## 模板

### 1. 需求真伪拆解

```text
背景：需求方提出【原始需求原话】，他的角色是【…】，业务场景是【…】。
任务：先别给方案，帮我判断这是不是真需求：
1) 他说的“问题”和“他想要的解法”分别是什么，两者是否对应；
2) 不做会怎样？谁受影响、影响多大、多久一次；
3) 有没有更便宜的办法达到同样效果；
4) 如果一定要做，最小可交付是什么。
输出：结论 + 三条追问（我要拿去问需求方），不要给技术方案。
```

### 2. 方案对比（决策矩阵）

```text
背景：要在【A/B/C】之间选，场景是【…】，我的约束是【工期、人力、预算、技术栈】。
任务：用决策矩阵对比。
要求：
1) 维度由你提，但每个维度要说清“为什么它对这个决策重要”；
2) 给每个维度定权重（合计 100），并说明权重依据我的约束怎么来的；
3) 打分时只用事实，缺数据就标【无数据】，不要猜；
4) 最后给推荐，并写明“如果权重变成 X，结论会翻转成哪个”。
输出：表格 + 一段不超过 200 字的结论。
```

### 3. 调研（竞品 / 工具 / 方案）

```text
背景：我要调研【领域/产品】，目的是【选型 / 定价参考 / 做差异化】。
任务：给一份调研框架 + 首轮初稿。
要求：维度固定为——它解决什么问题、目标用户、核心能力、明显短板、定价模式、可替代性；每条结论后面标信源（官方文档 / 用户评价 / 我的推测），推测必须显式标注；
不确定的直接写“未查到”，不要用行业常识填空。
```

### 4. 数据解读

```text
背景：这些是【业务指标】在【时间段】的数据：【贴数据或表格】。
任务是：不要罗列数字，回答三个问题——发生了什么变化、最可能的两个原因分别是什么、还需要什么数据才能确认。
要求：区分“相关”和“因果”；指出数据本身的局限（口径、样本量、季节性）；不要给“建议加强运营”这种无法执行的结论。
```

### 5. 上线风险评估

```text
背景：要上线【功能】，涉及【表结构变更 / 接口变更 / 第三方依赖】，影响【用户量/调用方】。
任务：给风险清单，按“发生概率 × 影响面”排序，每条包含：触发条件、表现、检测方式、止损动作（具体到命令或开关）、责任人。
要求：至少覆盖数据兼容、灰度、回滚、依赖超时、并发峰值、监控盲区六项；没有兜底手段的项要明确写“无兜底，风险自担”。
```

### 6. 业务 / 项目复盘

```text
背景：项目【名称】，目标【原定指标】，实际【结果】，周期【…】。
任务：写复盘，结构——目标与结果对照 / 关键动作与效果（哪些有效、哪些无效）/ 失真原因（判断、执行、外部）/ 可复用结论 / 下次怎么做。
要求：只写有证据的结论；区分“运气”和“能力”；每条结论要能被下一个项目直接执行。
```

### 7. 成本收益测算

```text
背景：要做的事是【…】，投入【人力/时间/钱】，预期收益【…】。
任务：给一个粗算模型：一次性成本、持续成本、收益口径、回本周期，并做三档估算（乐观/中性/悲观）。
要求：每个数字标来源（报价 / 历史数据 / 假设）；假设单独列一节；最后给“什么条件下这件事不值得做”。
```

### 8. 反方视角（red team）

```text
背景：我倾向的方案是【…】，理由是【…】。
任务：站在反方，尽可能有力地证明我错了：
1) 我的论证里哪些是假设而非事实；
2) 这个方案最可能怎么失败（按时间顺序描述失败路径）；
3) 如果一个比我资深的人反对，他最可能说什么；
4) 什么证据能让我改变主意。
要求：不要客套，不要“但也可能对”，要给可被检验的反驳。
```

### 9. 优先级排序

```text
背景：待办清单如下【列表】，我的资源是【人/时间】。
任务：按“价值 ÷ 成本”排序，价值用【影响用户数 × 严重程度】，成本用【人日】估。
要求：先给排序结果，再给每项的估值依据；指出哪些是“做了也看不出来”的低感知项；给出“如果只能做三件，做哪三件”。
```

### 10. 决策记录（ADR 风格）

```text
背景：我们已经决定【方案】，做了【…】的取舍。
任务：写成一份决策记录：背景 / 备选方案 / 决定 / 理由 / 已知代价 / 复核条件（什么情况下重新评估）。
要求：写清“当时不知道什么”，方便半年后的人理解这不是拍脑袋；不要美化决策过程。
```

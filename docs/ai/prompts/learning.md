# 学习与理解提示词（9 条）

> 学新东西、读源码时用的 9 条。锚定我的水平，并留一个验收动作。
> 通用骨架：背景 → 现状 → 目标 → 约束 → 输出格式，见 [提示词库总览](/ai/prompts/)。

## 模板

### 1. 概念讲解（分层 + 类比 + 边界）

```text
背景：我想搞懂【概念】，我已知【我熟悉的相关知识，比如“会用 Redis 但不懂持久化细节”】。
任务：按三层讲——
1) 一句话是什么（给一个生活化类比）；
2) 它解决什么问题、不解决什么问题；
3) 在我熟悉的技术栈【…】里，它体现在哪、什么时候会用到。
要求：不要从历史讲起；不要罗列 API；每层讲完停一下，等我确认再继续。最后给我三个“我以为对其实错”的常见误解。
```

### 2. 源码 / 机制逐层拆解

```text
背景：我要读懂【类/机制】，代码在【贴关键代码或版本号】，我的目标是【改它 / 排查问题 / 面试】。
任务：按调用顺序讲，每一层回答三件事——这层做什么、关键变量在这一步是什么值、如果它出错会表现成什么现象。
要求：只讲和我的目标相关的路径，跳过无关分支；每一层标出对应的源码行或方法名；不确定的地方直接说“这里要跑一下才确定”。
```

### 3. 论文 / 长文速读

```text
背景：这是一篇【领域】的论文/长文：【贴链接或全文】。
任务：给我四段输出——它要解决什么问题、方法的核心思路（用三段话讲清，不用公式）、实验结论到底证明了什么、它的局限和适用边界。
要求：区分“作者声称的”和“实验支持的”；术语第一次出现时给一句解释；如果我没读原文也能用这份笔记做判断，就算合格。
```

### 4. 长内容提炼（书 / 文档 / 会议录音稿）

```text
背景：这份材料是【类型】，我要用它来做【写方案 / 做分享 / 快速决策】，可用时间只有【N】分钟。
内容：【贴全文或分段贴】
任务：分层提炼——一页纸结论（5 条以内）/ 支撑结论的关键论据 / 可直接引用的原话（带位置）/ 我可能误解的地方。
要求：不要按原文顺序复述；按重要性重排；每条结论注明出自哪一节。
```

### 5. 面试追问模拟

```text
背景：我在准备【岗位】面试，简历里写了【项目/技术】。我的实际水平是【…】。
任务：当面试官，针对【主题】连续追问 5 轮，每轮只问一个问题，根据我的回答决定往深还是换方向。
规则：我答错时先不纠正，继续追问到暴露问题为止；五轮结束后统一给出——哪几轮答虚了、正确的答法、下次该怎么组织语言。
```

### 6. 30 天学习计划（任务驱动）

```text
背景：我要在【N】周内学会【技能】，目的是【做项目 / 面试 / 工作中马上用】，每周可投入【X】小时，我的基础是【…】。
任务：给一份任务驱动的计划，不是课程目录。
要求：每周一个可验证的产出（能跑的东西 / 能讲清楚的笔记）；每个任务写明“卡住时查什么”；砍掉和目的一周内无关的内容；最后给三条“如何判断自己真的会了”。
```

### 7. 费曼自测（让它出题 + 挑错）

```text
背景：我刚学完【知识点】，下面是我的理解（可能有错）：【用大白话写一段】。
任务：1) 指出我理解里错的和含糊的地方，逐条对应到我原话；2) 出 5 道题，2 道基础、2 道边界、1 道场景题；3) 我答完后按“概念准确度 / 边界意识 / 表达清晰度”三项打分。
要求：不要鼓励式评价，错就是错，说清错在哪。
```

### 8. 对比式理解（两个相近概念）

```text
背景：我分不清【A】和【B】，已知【我对两者的模糊理解】。
任务：用四栏对照讲清——解决的核心问题、典型使用场景、代价和限制、什么时候会选错。
要求：给一个“同一业务场景下两者分别怎么写”的具体例子；最后给一句能在面试里直接说的区别总结。
```

### 9. 知识地图串联

```text
背景：我零散学过【知识点列表】，感觉是散的。
任务：画一张知识地图——哪些是基础依赖、哪些是并列关系、哪些是上层应用，并标出我理解这些之前必须先懂什么。
输出：用缩进列表或 mermaid 图给结构，每个节点一句话说明它解决了上层哪个痛点；最后指出我列表里缺的关键前置知识。
```

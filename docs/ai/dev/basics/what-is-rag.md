# RAG 是什么

> 先检索，再生成。把私有文档切块、向量化、召回相关片段，再交给模型回答——减少胡编，回答能对上来源。

## 流程（记四步就够）

1. **入库**：文档切块 → 向量化 → 写入向量库/索引  
2. **提问**：用户问题同样向量化  
3. **召回**：找出最相关的若干片段  
4. **生成**：把片段当上下文，再让模型作答（可要求引用出处）

## 知识库从哪来

先小后大，先能检索再谈优化。常见来源：

- 简历、面试笔记、项目 README  
- 业务文档、Wiki、接口说明  
- 会议纪要、规范、FAQ  

不必一上来追求「全公司知识库」；一份 Markdown 目录跑通闭环即可。

## 和 Agent 的关系

- **RAG**：给模型「可引用的私有知识」  
- **Agent**：模型 + 工具 + 循环，去「做事」  

Agent 可以把检索当成一个 Tool，但 RAG 本身不是 Agent。概念入门到此即可；落地见 [Agent 应用开发](/ai/dev/agent/)。

选型与场景见 [模型选择指南](/ai/explore/model-selection)。

# AI 工具与选型

> 信息截至 2026-11，具体工具名单每季度复核一次；判断标准不随版本变化。
> 一句话：没有“最好的 AI”，只有“最匹配这类任务的那一类”。

## 场景与问题

“哪个 AI 最好？”是被问得最多、也最没意义的问题。写代码、写周报、查一个技术方案、生成一张封面图，这些任务对模型能力、上下文长度、联网搜索、图像生成的要求完全不同。用通用聊天模型硬啃代码重构，或者用代码专用工具去写公众号文章，都是别扭的：不是做不了，是事倍功半，还容易在错误的地方翻车。

工具越来越多，发布会每周都有。追着新模型跑，时间会被切得很碎，什么都浅尝辄止——这和我见过的“团队引入新框架，热闹三个月没人用了”是同一个毛病。

还有两个更实际的问题：一是**选错工具的返工成本很高**，该用编程助手的地方硬用通用对话，代码上下文全靠手动粘贴；该本地处理的代码，被传给了公有云接口。二是**成本**，工具开一堆订阅，每月几百块，真正常用的可能就两个。

所以这一篇只解决三件事：把工具分成几类看清楚、用一套标准挑、按自己的任务分布决定付多少钱。

## 一、五类工具，各管一段

绝大多数工具可以归为五类，同类能力高度重叠，会用一个，迁移成本很低。

| 类别 | 解决什么问题 | 代表工具（2026-11） | 选的时候最该看什么 |
|------|------------|------------------|------------------|
| 对话类 | 问答、分析、写作、头脑风暴 | ChatGPT、Claude、Gemini、DeepSeek、豆包 | 中文质量、长文本理解、推理深度 |
| 编程类 | 写代码、改 bug、代码评审 | Claude Code、Cursor、GitHub Copilot、Codex 类工具 | 项目级上下文、能否跑命令、模型可切换 |
| 生图类 | 配图、海报、UI 草图 | Midjourney、DALL·E、Stable Diffusion、即梦 | 风格控制力、中文文字渲染 |
| 生视频类 | 短视频、演示动画 | Sora、Runway、可灵、Vidu | 时长、跨帧一致性、可控性 |
| 办公类 | 文档、表格、PPT、会议纪要 | 飞书智能伙伴、Notion AI、Office Copilot | 与现有工作流的集成度 |

分类不是为了背名单，而是养成一个定位习惯：拿到任务先问“这是哪类问题”，再从对应类别里挑。跨类别硬用往往最费时间——用对话类做生图，或用办公插件做代码重构。

## 二、判断工具好坏的四个标准

1. **效果**：能不能稳定产出可用结果。判断方法很朴素——拿你自己真实场景里的 3~5 个任务去测，不要用官方 demo。demo 都是挑过的。
2. **成本**：不只是订阅费，还有迁移成本和学习成本。一个每月 20 美元但要重建整套工作流的工具，未必比免费但能直接用的划算。
3. **可控**：结果能不能稳定复现、能不能精细调整。生图能不能控构图，编程助手能不能按你的规范改代码，对话能不能记住项目背景。不可控的工具只能当玩具。
4. **数据安全**：你的代码、文档、客户数据会不会被用于训练？能不能私有部署？个人练手无所谓，接公司项目必须先问这一条。

## 三、按任务对号入座

- **写代码**：优先用带代码库索引、能直接改文件、能跑命令的工具。纯聊天模型给的代码片段看起来漂亮，放进真实项目往往缺依赖、缺上下文，接缝要自己磨。
- **写文档**：通用对话模型更合适。长文结构、语气调整、多版本改写，这类工具的交互更顺。终稿自己过一遍，事实必须自己核。
- **查资料**：需要联网的场景用带搜索能力的工具。注意区分“搜到的”和“模型编的”，要求它给来源链接，重要结论点开原文核一遍。
- **生图**：用专门的图像生成工具。文字模型的生图能力普遍是附赠水平，产出看运气。
- **翻译与润色**：通用对话模型即可，但要给语气样例和术语表，否则译文一股“翻译腔”。
- **数据处理**：让 AI 写代码（Python / pandas）比让它直接算靠谱——它心算容易在细节上出错，写代码你可以跑验证。

## 四、别只看单点，看组合

实际工作里任务是串起来的：查资料 → 定方案 → 写代码 → 写文档，对应一条工具链。

- **对话 + 编程**：先让对话类把需求拆成方案，喂给编程助手落地，再回到对话做代码评审式追问。
- **对话 + 生图**：先用对话把需求写成结构化提示（主体、风格、构图、比例），再投给生图工具，比裸写提示稳定得多。
- **办公 + 对话**：会议纪要、长文档先在办公工具里沉淀，再用对话做摘要、抽待办、生成汇报。

拿“给项目写一篇 README”这种混合任务拆一下，就能看出组合的价值：

1. 结构：通用对话模型按“简介 / 快速开始 / 配置 / 常见问题”给骨架。
2. 技术细节：把真实代码库丢给编码工具，让它按实际入口和配置项填命令——这部分通用模型只能编。
3. 措辞：回到通用模型调语气和段落。
4. 终审：自己对着仓库跑一遍命令，确认每条都能执行。

只用一个工具硬扛，出来的 README 必然一半靠谱一半是编的。

组合里两个约束：数据在工具之间流转的路径要过一遍安全红线；环节不宜超过三个，环节越多衔接损耗越大，先证明两步有收益再加第三步。

## 五、成本：按时间占比付费

- **先统计任务分布**：记一周，写代码多少小时、写文档多少小时、查资料多少次。工具优先级跟着时间占比走，写代码占一半就先为编码工具付费。
- **免费额度先试两周**：同一类任务拿手头的真实问题对比两个工具，看产出直接可用的比例，别看演示视频。
- **看“可用率”而不是“惊艳率”**：偶尔一次惊艳不值钱，80% 情况下拿来就能用才值钱。稳定比上限重要。
- **工具总数控制在三个以内**：每多一个工具，多一份订阅费、一套习惯成本、一个“这事该用哪个”的决策开销。
- **付费退订要干脆**：连续一个月没打开的订阅就是纯亏，砍掉。年付优惠看着划算，但工具迭代极快，先月付验证习惯再考虑年付。
- **留意用量限制**：重度任务撞上限速，在关键时刻掉链子，比贵一点更伤。

## 六、换新工具：用同一组任务打分

换工具别凭第一印象，用同一批真实任务跑两轮：

- **任务样本**：从本周实际工作里挑 5 个有代表性的问题，覆盖你最常做的那类任务，不要挑工具擅长的演示题。
- **打分维度**：直接可用率（不用改就能用）、修改后可用率、响应速度、成本。
- **结论**：两周后把两次记录并排看，留总分高的，另一家退订。

## 七、国产与海外的现实权衡

除了类别和四条标准，还有一个维度是能不能用、能不能合规地用：

- 海外工具在部分任务上仍领先，但要考虑网络门槛、付费方式和数据出境。
- 国产工具在中文语境、本土办公生态（飞书、钉钉、企微）和访问稳定性上更省心，能力差距在快速缩小。
- 接企业项目优先选有国内合规部署方案的；个人探索再考虑海外服务。

对多数人的务实策略：**主线用一到两个能稳定用的工具保证日常产出，同时保持对海外工具的低频观察**，差距真正拉大到影响重要任务时再切换。

## 八、不追新，但别闭眼

- 新模型发布和可用之间常有几周到几个月的差距，等它稳定再上，损失不大。
- 同类工具能力在快速拉平，今天 A 比 B 强 20%，下个季度可能就反过来。
- 追新最大的代价是注意力。省下的时间，不如把主力工具练到熟练。

一个实用信号：**新工具在你的场景里明显好于现用的，且好到能抵消迁移成本，才值得换**。否则先观望。

配套动作：每月留 2 小时集中试用新东西，其余时间不打断主线——好奇心有出口，专注也不被切碎。建一张自己的工具清单：每类记 1~2 个主力 + 1 个备选，注明用在哪、多少钱，每季度回顾一次，而不是每周。

## 九、起步：先用后学

选完了工具，最后一步是“怎么开始用”。结论很反直觉：**不要在会用之前去学原理**。

1. **直接拿真实任务上手**，允许自己只会最基础的操作。
2. **卡住了再去查**，带着具体问题查，查到的东西立刻用回这个任务。
3. **一个练习只练一个点**，控制在 30 分钟到 2 小时内完成，且产出可见（把 50 页文档总结成一页要点、给老项目加一个带单测的接口、用同一提示词出 5 张图挑能用的）。
4. **任务优先级 = 频率 × 花费时间 × 现在多烦**。每周耗你两小时的周报，就是最好的第一个练习对象，练完立刻每周赚回两小时。

三个防坑动作：同一时间只保留一个主线学习材料（一进一出）；教程只当字典，跳读查章节而不是从头看到尾；任何教程给固定预算（比如 3 小时），到期必须产出一个小闭环，产不出就换。

## 关键要点

- 没有“最好的 AI”，只有“最适合这类任务的 AI”：先分类，再对号入座。
- 五类工具各管一段，跨类别硬用最费时间；同类工具能力高度重叠，迁移成本低。
- 四条判断标准：效果（真实任务测）、成本（含迁移）、可控（能否复现与微调）、安全（数据能不能出去）。
- 任务是链条，工具也用组合，但环节控制在三个以内。
- 按时间占比决定给谁付费；看可用率而不是惊艳率；不用的订阅果断砍。
- 主线稳定、海外低频观察，等差距影响到重要任务再切换。
- 起步先上手再补原理：真实任务、最小闭环、教程当字典。

## 小结

选工具的本质是任务匹配：先把自己的任务分类，再让每类任务落到合适的工具上，中间用组合把链路串起来。成本控制的核心不是省钱，是把钱花在时间占比最高的任务上。工具名单会一年一换，但“先分类、按真实任务评测、按使用率付费、不追新按需换”这四条可以一直用下去。

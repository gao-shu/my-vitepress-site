# Hooks / Scripts · 自动化执行

> 第一层 · 能力底座。解决「哪些检查不该靠提示词提醒」——凡是"漏了就出事、且能脚本判定"的事情，交给脚本和 Hooks 自动执行，不依赖 AI 记得。

## 解决什么问题

- 靠提示词提醒「记得跑测试」，AI 偶尔就忘了。
- 同样的问题反复靠人肉检查，浪费时间。
- 密钥、禁改区这类红线，只在口头说过，没有自动拦截。
- Hooks 装了一堆，误报太多，最后全被忽略。

## 核心内容

### 什么交给脚本

满足两个条件就该脚本化：

1. **漏了就出事**：不检查可能导致错误交付（构建失败、测试没过、密钥泄露）。
2. **能明确判定**：结果是非黑即白，不需要业务判断。

典型场景：

- 构建、类型检查、单测。
- 密钥 / 敏感信息扫描。
- 禁改区 diff 检查。
- 遗留文件清理（临时文件、调试代码）。
- 提交前格式与 lint。

**需要业务判断的不交给脚本**：业务规则对不对、架构是否合理、需求理解是否准确——这些留给审查和人判定。

### Hooks 与 Scripts 的分工

| 方式 | 适合做什么 | 特点 |
| ---- | ---------- | ---- |
| Scripts | 独立的检查、清理、验证 | 显式调用，可单独跑，好调试 |
| Hooks | 在特定时机自动触发（如提交前） | 强制生效，但误报会打扰 |

建议：先把检查写成能独立运行的脚本，确认稳定后，再把最关键的那几个挂到 Hook 上。**不要一上来就挂一堆 Hook**。

### 设计原则

- **快**：检查要能快速给结果，慢检查单独跑，不阻塞日常操作。
- **准**：只报确定的问题，宁可少报不要误报，否则会被忽略。
- **可解释**：报错要说清「哪里不对、怎么改」，不只是「失败」。
- **能跳过有记录**：确需跳过时留痕并说明原因，不是静默忽略。

### 工具适配边界

Hooks 的具体配置语法和触发时机因工具而异，以所用工具当前版本官方文档为准。本页只约定「什么该自动化、怎么设计检查」，不绑定某个工具的写法。

## 检查脚本清单模板

```markdown
# <项目名> 自动化检查清单

| 检查项 | 脚本/命令 | 触发时机 | 失败处理 | 能否跳过 |
| ------ | --------- | -------- | -------- | -------- |
| 构建   | <命令>    | 提交前   | 必须修复 | 否 |
| 单测   | <命令>    | 提交前   | 必须修复 | 否 |
| 密钥扫描 | <命令>  | 提交前   | 立即处理 | 否 |
| 禁改区 diff | <命令> | 提交前 | 人工确认 | 需记录 |
| 格式/lint | <命令> | 提交前 | 建议修复 | 是 |

## 说明
- 哪些检查挂在 Hook 上：<列表>
- 跳过规则：<如何留痕>
```

## 可复制提示词

<details>
<summary><strong>把重复检查固化为脚本</strong></summary>

```text
下面这些检查我们每次都要手动做，请帮我设计成可复用的脚本方案。本轮只输出方案，不写代码。

检查清单：
<粘贴每次都做的检查>

对每项请判断：
1. 是否「漏了就出事」且「能明确判定」——是则适合脚本化，否则说明留给人工审查。
2. 给出脚本要做的事、输入输出、失败时的报错信息（要说清怎么改）。
3. 建议触发时机：显式运行 / 提交前 Hook。

约束：
- 只把最关键、最稳定的检查挂到 Hook，避免误报打扰。
- 慢检查单独跑，不阻塞日常操作。
- 需要跳过的检查给出留痕方式。

输出：适合脚本化的清单 + 每项方案 + 建议挂 Hook 的最小集合。
```

</details>

<details>
<summary><strong>审查现有 Hook 是否过载</strong></summary>

```text
请审查当前项目的 Hook/自动化检查配置，判断是否过载，只输出分析，不修改配置。

<粘贴现有 Hook/检查清单>

检查项：
1. 哪些检查误报率高、实际很少拦住真问题。
2. 哪些检查太慢，拖慢日常操作。
3. 哪些检查需要业务判断，不该自动化。
4. 是否有「漏了就出事且能脚本判定」但没被覆盖的检查。

输出：建议移除的、建议改为显式运行的、建议新增的，各给理由。
```

</details>

## 验收要点

- [ ] 脚本化的检查都满足「漏了就出事 + 能明确判定」。
- [ ] 需要业务判断的检查留在人工审查，没有强行脚本化。
- [ ] 检查快、准，报错可解释。
- [ ] Hook 只挂最关键最稳定的几个，没有误报轰炸。
- [ ] 跳过检查有留痕方式。

能自动化的不要靠记忆，需要判断的不要硬自动化。分清楚这两类是关键。

# AI 辅助软件开发规范

> 一套可落地的工程规范，分三篇。遇到任务直奔对应的一篇，照着做、复制提示词、拿证据验收。不是教程书，也不需要每次从头读到尾。

## 三篇手册

| 篇 | 解决什么 | 什么时候翻 |
| -- | -------- | ---------- |
| [第一层 · AI 工程基础](/ai/productivity/dev-spec/01-foundation) | 让 AI 懂项目、守规则、有技能、会分工、能调工具、自动检查 | 配置 AI 开发环境、接手新项目、老出错要补底座 |
| [第二层 · 软件开发生命周期](/ai/productivity/dev-spec/02-lifecycle) | 从准备到交付九个阶段怎么做 | 接到开发任务，从开工到收工 |
| [第三层 · 质量与安全保障](/ai/productivity/dev-spec/03-quality) | 代码质量、测试、安全、Git、变更、回滚 | 每次改动全程对照，交付前逐条过 |

三层关系：**第一层是能力底座，第二层是执行流程，第三层贯穿前两层全程**（不是收工才检查）。

```text
① 配置底座（第一层）→ 项目信息、规则、技能、分工、工具、自动化检查
② 执行任务（第二层）→ 准备 → 需求 → 架构 → 开发 → 审查 → 修复 → 优化 → 测试 → 交付
③ 全程把关（第三层）→ 质量 · 测试 · 安全 · Git · 变更 · 追踪回滚
```

## 怎么用

- 改文案、明确小修：直接从第二层「功能开发」开始 + 第三层局部检查。
- 接手陌生项目：先看第一层「Project Context」，再走第二层「项目准备」。
- 复杂功能 / 老项目改造：三层完整走，第二层九阶段按任务分级裁剪强度。
- 出错、测试失败、准备交付：第二层「审查 / 修复 / 测试 / 交付」+ 第三层全程清单。

判断标准：**改错了要回滚多个文件，就按完整流程走**；否则按最轻的合理路径执行。

> 具体工具的目录名、配置语法以各工具当前版本官方文档为准，本文只约定「做什么、怎么验收」。可直接复制的零散提示词另见 [提示词库 · 编程开发](/ai/prompts/coding)。

# 03 技术架构设计

> 第二层 · 开发生命周期。解决「避免 AI 没定方案就动手，写到一半发现方向错了」——复杂任务先出方案、比较取舍、明确修改范围和风险，再进入编码。

## 什么时候用

- L2 普通任务：分析影响后给简要方案。
- L3 复杂任务：完整方案 + 风险清单 + 分阶段计划。
- L1 简单任务：跳过本阶段，直接开发。

**判断标准：如果方案错了要回滚多个文件或改数据结构，就必须先设计。**

## 操作步骤

### 方案回答五个维度

| 维度 | 要说明什么 |
| ---- | ---------- |
| 数据 | 表、索引、约束、迁移、事务 |
| 接口 | 路径、入出参、错误码、兼容性 |
| 模块与分层 | 落在哪个包、依赖方向 |
| 兼容与影响 | 老数据、调用方、开关、定时任务 |
| 验证方式 | 哪些测试、哪些命令、哪些人工核对 |

### 多方案比较与取舍

凡有多种做法，给出可选方案并比较：改动范围、数据影响、兼容性、回滚成本、验证难度。

取舍顺序：**业务正确性 → 兼容性 → 改动范围 → 复用 → 可验证性 → 代码美观**。

### 明确修改范围三栏

```text
允许修改：
- backend/.../service/WorkOrderService.java
- web/src/api/mes.ts

禁止修改：
- 任何已有接口路径与方法签名
- legacy/ 目录下的历史逻辑
- pom.xml、package.json（本次不新增依赖）

必须保持兼容：
- GET /api/mes/work-orders 的返回结构
- 现有状态机的流转规则
```

同时写出「本次不做项」——防止 AI 按自己的理解顺手扩大范围。

### 风险清单与拆解

风险写成「风险 → 触发条件 → 影响 → 处理 → 谁确认」，不写「可能有风险」这种执行时不知道怎么处理的话。

方案通过后拆成子任务：能独立完成、能独立验收、一次提交能覆盖。按依赖顺序排：`数据层 → 后端服务 → 接口层 → 前端 → 测试 → 文档`。前后端并行有前提——接口契约先冻结。

子任务完成标准写成命令、diff 特征或页面行为，不写「完成开发」。

## 可复制提示词

<details>
<summary><strong>生成技术方案（本轮不改代码）</strong></summary>

```text
你的任务只有一个：基于已有上下文产出技术方案和风险清单。本轮不要改代码、不要建文件。

任务：<一句话>
已有上下文：涉及模块与文件、相关调用链、数据库与接口现状、已知约束与禁改区。

按以下结构输出：
1. 需求复述（三句话内）
2. 仍模糊且会影响实现的问题（按影响排序）
3. 本次不做项
4. 方案比较（给出可选方案，逐项对比改动范围、数据影响、兼容性、回滚成本、验证难度）
5. 推荐方案与理由（按业务正确性 → 兼容性 → 改动范围 → 复用 → 可验证性排序）
6. 修改范围三栏（允许修改 / 禁止修改 / 必须保持兼容）
7. 风险清单（风险 → 触发条件 → 影响 → 处理 → 谁确认）
8. 子任务拆解（编号 | 任务 | 涉及文件 | 依赖 | 完成标准 | 验收方式）
9. 执行顺序与检查点
10. 需要我拍板的问题（没有就写「无，可以开始」）

不要输出实现代码；不要编造项目里不存在的组件或服务；无法判断的标「待确认」。
```

</details>

<summary><strong>表结构与接口契约评审</strong></summary>

```text
请评审下面这次涉及的数据结构和接口契约，本轮只评审，不改代码。

表结构变更：<粘贴 DDL 或字段说明>
接口变更：<路径、入参、出参、错误码>

请检查：
1. 字段类型、长度、非空约束、索引是否合理，是否影响已有数据。
2. 迁移脚本能否重复执行，回滚是否可行。
3. 接口入出参是否兼容已有调用方，错误码是否完整。
4. 是否有幂等、并发、租户、权限方面的遗漏。
5. 前端契约与后端 DTO 是否一致。

每条问题给「问题 → 影响 → 建议」，并标严重程度。没问题的项也明确写「已检查，无问题」。
```

</details>

## 验收要点

- [ ] 方案覆盖数据、接口、模块、兼容、验证五个维度。
- [ ] 写出本次不做项和修改范围三栏，落到具体文件路径。
- [ ] 多方案有比较，取舍理由符合优先级。
- [ ] 风险清单每条有处理动作和确认人。
- [ ] 子任务能独立执行、独立验收，完成标准可核对。
- [ ] 需要人拍板的事项已拍板；没有编造不存在的组件。

方案通过进入 [04 功能开发](/ai/productivity/dev-spec/02-lifecycle/development)。接口与数据的变更控制按第三层 [变更控制](/ai/productivity/dev-spec/03-quality/change-control) 执行。

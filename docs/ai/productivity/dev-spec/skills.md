# 开发 Skill 示例库

> 可直接复用的开发 Skill 示例。每个 Skill 是一个独立、可调用的能力单元；这里统一展示和管理，按需取用。

## 快速定位

| 我现在要做什么 | 找哪个 Skill |
|---|---|
| 分析项目、建立项目上下文 | project-analysis-skill · project-context-skill |
| 多 Agent 协作、代码审查、调试 | agents-skill · code-review-skill · debugging-skill |
| 测试、发布交付 | testing-skill · release-skill |
| RAG / Agent / MCP 应用开发 | rag-development-skill · agent-development-skill · mcp-development-skill |

> **说明**：下面的分类只是示例，不代表全部已开发。当前先落地 `agents-skill` 作为第一个完整样板，其余按同一规范逐步补充。

## 三个概念

| 概念 | 作用 |
|---|---|
| Skill 示例库 | 展示、管理和复用各种 Skill（本页） |
| 独立 Skill | 解决某一类具体问题，独立可调用 |
| Skill 调用机制 | 判断何时调用、如何执行 |

> **原则**：不让一个总 Skill 包办所有事情，否则容易变成庞大、难以维护的提示词。

## 样板 · agents-skill

**多 Agent 协作开发。** 把「任务评估与分工 → 协同执行 → 汇总验收」三个阶段封装成独立 Skill。你只需提出开发任务，主 Agent 根据任务情况决定是否调用它。

### 什么时候使用

- 任务可拆分、可并行
- 需要独立审查
- 任务复杂，需要多个专业角色

### 操作

#### ① 多 Agent 协作开发

一次提交完整任务，自动完成「评估分工 → 执行 → 统一验收」三个阶段。你只需发起一次任务，三个阶段是主 Agent 内部的工作流程，不需要手动分三次输入提示词。

```text
请评估下面的任务是否适合使用多 Agent 协作。如果适合，请自动完成任务拆分、分工、执行和最终验收；如果不适合，请说明原因，并建议使用单 Agent 完成。

任务：
<填写具体任务>

## 阶段一：任务评估与分工设计
1. 分析任务是否可以拆分为相对独立的子任务。
2. 检查任务之间的依赖关系、文件冲突和共享接口。
3. 判断多 Agent 是否比单 Agent 更高效。
4. 如果不适合多 Agent，说明原因并停止多 Agent 编排。
5. 如果适合，设计最小化分工方案。

分工要求：
- 明确每个 Agent 的职责和具体任务。
- 明确允许修改、只读和禁止修改的文件范围。
- 明确共享接口、数据结构和协作约定。
- 明确任务依赖和执行顺序。
- 指定主 Agent 负责协调、汇总和最终验收。

## 阶段二：执行任务
1. 按照分工启动各 Agent 执行任务。
2. 在任务允许的情况下并行执行，存在依赖时按顺序执行。
3. 各 Agent 严格遵守任务边界和项目开发规范。
4. 遇到重大设计问题、需求不明确或任务冲突时，暂停相关任务并反馈。
5. 主 Agent 持续协调进度，处理协作问题。
6. 各 Agent 完成后，汇报修改文件、实现内容、测试结果和遗留问题。

## 阶段三：汇总结果与统一验收
主 Agent 收集所有 Agent 的执行结果，并结合实际代码变更和 Git Diff 进行统一检查。

检查内容：
1. 是否完成原始需求。
2. 是否超出任务和文件修改范围。
3. 是否存在文件覆盖、修改冲突或重复实现。
4. 各模块之间的接口和数据结构是否一致。
5. 业务逻辑、异常处理和边界条件是否正确。
6. 是否存在代码质量问题。
7. 测试是否充分，是否有真实执行证据。
8. 是否存在遗留问题或潜在风险。

发现问题后：
- 明确且影响较小的问题，可以安排对应 Agent 修复。
- 涉及多个模块的问题，先协调相关 Agent 确认方案。
- 重大设计问题、需求偏差或超出原始范围的问题，先向用户说明。
- 修复完成后，重新检查代码并执行必要测试。

## 最终交付
请输出统一的执行报告：
1. 多 Agent 使用评估及分工情况。
2. 各 Agent 任务完成情况。
3. 实际修改文件及核心实现。
4. 发现的问题及修复情况。
5. 测试执行情况及结果。
6. 未解决的问题和遗留风险。
7. 最终验收结论：通过 / 有条件通过 / 未通过。

注意：
- 不得仅凭 Agent 自述判断任务完成。
- 不得将未执行的测试标记为通过。
- 不得擅自扩大修改范围。
- 不得隐瞒未完成事项。
- 最终验收由主 Agent 负责。
- 如果当前编程工具不支持子 Agent 创建、任务调度或并行执行，必须明确说明这一能力限制，不能假装已经启动了多个 Agent。
```

### 完成标准

> **一次任务拿到完整执行报告：评估、分工、执行、统一验收全部完成；验收结合真实代码和 Git Diff，不靠 Agent 自述，未执行的测试不算通过。**

# Cursor 老项目实战

接手已有仓库时的固定顺序。文件模板只用 [项目落地包](/ai/dev/coding/project-landing-kit)，本页不另起一套示例。

适用：Java / Spring 外包接手、二开、加一个小功能。  
原则：**先读代码写文档，再改代码。**

下文用落地包里的工单项目说明。你的仓库把 `ticket` / `biz_ticket` 换成真实模块名即可。

---

## 0. 第一天禁止事项

- 不要让 AI 「重构整个项目」
- 不要先装一堆 Skill
- 不要在没有 `99-gotchas.md` 时改对外接口

---

## 1. 只扫描，写入规定文件

一次只生成一个文件，生成后你自己改掉猜错的句子。

### 1.1 概览 → `docs/ai-context/00-overview.md`

```text
根据仓库依赖和启动类，写 docs/ai-context/00-overview.md。

必须包含这些标题，不要加别的大章：
# 项目概览
## 做什么
## 技术栈
## 本地启动
## 本阶段不做

规则：
- 只写代码里能看到的事实
- 看不出的启动方式写「待确认」
- 不要编业务背景
```

### 1.2 模块 → `docs/ai-context/01-modules.md`

```text
根据 Controller 写 docs/ai-context/01-modules.md。

必须包含：
# 模块
（表格：模块、职责、代码包）
## 调用链
（只写本次会碰的那一条，例如工单查询）
## 表
（只列相关表和字段，字段必须能在 Entity/XML 里对上）

看不对的字段写「待确认」，不要猜。
```

### 1.3 坑 → `docs/ai-context/99-gotchas.md`

你来写，不要让 AI 编。至少三条里能填则填：

```text
- 不能改的接口路径：
- 历史脏数据 / 兼容：
- 不要模仿的坏写法：
```

然后把落地包里的 `AGENTS.md` 和 `00-core.mdc` 放进仓库，技术栈改成扫描结果。

---

## 2. 用一个小改动验证规则

选改动面最小的需求。工单示例：**列表按 status 过滤**。不要第一次就做导出、重构、加中间件。

```text
阅读 AGENTS.md、docs/ai-context/00-overview.md、01-modules.md、99-gotchas.md。

任务：GET /api/tickets 增加可选参数 status。
先输出方案：改哪些类、条件怎么写、怎么验收。
不要改代码。
```

确认方案只动工单查询后：

```text
按方案改代码。

范围：仅工单查询相关类
禁止：改 URL、改表、改其他模块、加依赖
验收：
- status=OPEN 只返回 OPEN
- 不传 status 行为与改前一致
- 回复里给出 curl
```

---

## 3. 不过关就停

| 现象 | 处理 |
|------|------|
| 方案里出现登录、Redis、顺手优化 | 把禁令补进 `00-core.mdc`，重做第 2 步 |
| 字段和表对不上 | 先改 `01-modules.md`，不要继续写功能 |
| diff 出现无关文件 | 回滚无关文件，收紧「范围」再改 |

第 2 步通过之前，不接大需求。


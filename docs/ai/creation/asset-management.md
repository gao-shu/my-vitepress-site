# 内容资产管理

## 场景与问题

做内容一年后，资产散落的代价开始显现：

- 封面图散在下载文件夹，命名全是 `image(3).png`、`未命名-2.jpg`，找一张三个月前的封面要翻十分钟；
- 发过的文章版本混乱：博客一版、公众号改过一版、后来又更新过一版，不知道哪份是最新的，改错版本白改；
- 当时花大钱（时间或 API 费）生成的提示词、分镜表、工作流配置找不到了，同样的东西要重做一遍；
- 去年哪篇文章带来了最多的关注、哪类选题数据最好——没有任何记录，复盘全凭印象；
- 想复用一篇旧内容，原始素材（图、数据、引用链接）已失效，只能重新收集。

内容资产和代码一样，**没有归档和版本管理就会持续熵增**。区别是代码有 Git 兜底，内容资产通常什么都没有——直到你被"找不到、改错、重复造"折磨到受不了。

## 做法

### 1. 归档结构：三类资产，一棵目录树

先把资产分三类，各归各位：

- **素材（raw）**：生成的图/视频、收集的引用、截图、数据——原料；
- **成稿（published）**：各版本文稿、封面终稿、发布链接——成品；
- **数据（data）**：各平台发布记录与表现数据——反馈。

统一目录约定：

```
content/
├── assets/            # 素材
│   ├── images/        # 按项目或主题分
│   ├── video-raw/
│   └── prompts/       # 提示词、工作流配置（易被忽视但最值钱）
├── drafts/            # 生产中的草稿
├── published/         # 已发布成稿（按年月或主题）
│   └── 2026-10-ai-writing/
│       ├── final.md / final.psd
│       └── meta.md    # 发布链接、平台、日期
└── data/
    └── metrics.csv    # 发布数据台账
```

两条规则决定这套结构能不能活：

- **单一落点**：一个文件只有一个"正式位置"，临时文件进 `_inbox/`，每周清一次——混乱都从"先放着"开始；
- **命名即元数据**：`YYYY-MM-主题-类型-版本`（`2026-10-ai-writing-cover-v2.png`），不靠文件夹层级硬塞所有信息，文件名自己会说话。

### 2. 版本管理：成稿用版本后缀，资产清单用 Git

- **成稿版本**：`v1/v2/final` 后缀 + 修改日期；改稿前先复制出新版本，不覆盖旧文件——原则和"不改生产库"一样；
- **终稿唯一**：`final` 只有一个，谁是最终版永远明确；发布后如有修订，出 `v1.1` 并在 meta.md 记一句改了什么；
- **meta.md 是每篇内容的"README"**：源文件位置、各平台链接、用过的封面、提示词引用——一篇一个，5 行就够；
- **用 Git 管文本资产**：文稿、提示词、分镜表、metrics.csv 这类文本放进一个 Git 仓库，改动历史免费获得；二进制大文件（图/视频）不进 Git，用目录约定 + 元数据清单管理（或用素材管理工具）；
- 关键资产（提示词库、模板库）单独成仓，和文章仓库分开，方便跨项目复用。

### 3. 可检索：让"找到"变成一次查询

找得到的前提是**每个资产都带可搜索的描述**。三个层级：

- **文件名层**：命名规范里强制带主题词（上文的命名即元数据）；
- **清单层**：每个项目一个 `meta.md` / 素材清单，记"这是什么、从哪来、当时什么提示词生成"——生成类素材尤其要记配方（模型、提示词、参数），配方比单张成图更可复用；
- **标签层**：给素材打轻量标签（主题、风格、平台、可用状态），标签数量控制在个位数枚举值，标签一多就没人维护了。

检索习惯：**找东西超过 2 分钟，就停下来补索引**——说明这个资产缺描述或放错了位置，修索引比继续翻划算。AI 的用武之地在这里很明显：把清单丢给它做自然语言查询（"找那张深色系、带传送带意象的封面"），比肉眼翻目录快一个量级。

### 4. 复用标记：让旧资产重新上岗

资产的价值在于复用，给关键资产加两个字段：

- **`status`**：`reusable`（可直接复用）/ `needs-update`（数据旧了、需修订）/ `retired`（作废）；
- **`repurposed`**：记录这篇/这张被复用到哪里——哪篇长文拆成了哪几条短内容、发在哪些平台、效果如何（与分发台账打通）。

配合两个触发时机：

- **选题会扫一遍 `reusable`**：旧文章更新 30% 就能重发，旧素材直接做新封面，复用是最低成本的产能；
- **季度巡检**：过一遍 `needs-update`，技术类内容时效性强，一篇 2024 年的工具教程要么更新要么标 `retired`——**过期内容挂着比没有更伤信任**。

数据资产（metrics.csv）是复用的另一面：每次复盘问"上次类似内容的表现如何"，有台账就有答案，没有就只能靠猜。

## 关键要点

- 三类资产分树归档：素材/成稿/数据，外加单一落点和 `YYYY-MM-主题-类型-版本` 命名；
- 成稿管版本：不覆盖、final 唯一、meta.md 记链接与修订；文本资产进 Git，配方比成图更值钱；
- 可检索三层：文件名 → 项目清单 → 标签，找东西超 2 分钟就补索引，AI 做自然语言查询；
- 复用标记 status + repurposed，选题会扫 reusable，季度巡检清过期内容；
- 数据台账进归档体系，复盘时"上次怎么样"靠查询不靠印象。

## 小结

内容资产管理就是给自己的创作系统装上"版本控制 + 资产索引"：**目录树解决"在哪"，命名和 meta 解决"是什么"，Git 解决"改过什么"，状态标记解决"还能不能用"**。前期多花的每一分纪律，都会在找素材、复用旧文、季度复盘时成倍还回来——这是工程师做内容最不该缺的基础设施。

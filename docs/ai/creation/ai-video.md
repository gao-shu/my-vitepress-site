# AI 生视频实践

## 场景与问题

视频是当下传播效率最高的形态，但对写技术博客的人来说门槛高得离谱：

- 想把一篇文章做成 60 秒的视频，光分镜就要想一下午，拍什么、怎么转场全没头绪；
- 文生视频一条 5 秒，抽卡抽到崩溃——手指不对、物体穿模、镜头乱飘，一段 20 秒的镜头要 roll 十几次；
- 生成的片段画风每条都不一样，拼到一起像素材大杂烩；
- API 按秒计费，随便试试就几十块出去了，还不知道钱花在哪；
- 素材一堆散在下载文件夹里，两周后想找"那条城市夜景镜头"，根本找不到。

做过一阵子剧本→分镜→生图/生视频的链路之后，我的结论是：**生视频的成败在视频之外**——脚本决定成败，素材管理决定效率，成本控制决定能不能持续做。

## 做法

### 1. 分镜脚本：先写清楚，再花算力

生成前必须有一张分镜表，最小字段：

| 镜号 | 时长 | 画面内容 | 运镜 | 文案/字幕 | 生成方式 |
|------|------|---------|------|----------|---------|
| 01 | 3s | 深夜工位，屏幕亮着代码，推近 | 推镜 | "又一个线上问题" | 图生视频 |
| 02 | 4s | 报错日志滚动，特写 | 固定 | "日志里藏着答案" | 文生视频 |

写脚本时的几个硬规则：

- **先有文案后有画面**：把旁白/字幕写完，再为每句话配画面，而不是先生成一堆漂亮镜头再凑解说；
- **一镜一意**：一个镜头只表达一个信息，5 秒讲不了两件事；
- **不确定的镜头标记"可替代"**：生成不出来就换表现手法（图表、字卡），不跟单条镜头死磕。

分镜表本身就是给 AI 的指令清单——后面每一步都是照表执行。

### 2. 文生视频 vs 图生视频：怎么选

- **图生视频（先文生图，再图生视频）是我的默认路径**：先用生图模型出满意的单帧（可控、便宜、可精修），再让它动起来。画面质量和风格一致性远好于直接文生视频；
- **文生视频**只用于不需要精确控制的空镜/氛围镜头（城市空镜、粒子背景），随机性可接受；
- **镜头复杂度匹配工具能力**：大运镜、多物体交互、人脸口型是重灾区，能用"固定镜头 + 简单动作"表达就别用复杂调度；必须的复杂镜头才上高成本模型。

典型流程：**分镜表 → 文生图出关键帧（批量、挑图）→ 关键帧图生视频 → 逐镜检查 → 进剪辑**。关键帧阶段就把风格问题解决掉，不要等视频阶段返工。

### 3. 素材管理：编号 + 目录约定，第一天就执行

散素材是效率杀手。我的目录结构就三层：

```
project-xxx/
├── script/     # 脚本、分镜表
├── raw/        # 生成的原始素材
│   ├── 01/
│   ├── 02/     # 按镜号分目录，文件名带镜号
├── export/     # 成片、封面
└── meta.md     # 用了哪个模型/提示词/费用
```

- **文件名 = 镜号 + 版本 + 描述**：`01_v2_push-code.mp4`，一眼知道归哪、是第几版；
- **废片不删但也不混**：进 `_trash/`，防止三天后发现"其实第一版更好"；
- **meta.md 记录每镜的提示词和费用**，既是复盘依据，也是下次重跑的配方；
- 素材库分两层：项目内素材（本片专用）和公共素材库（可复用空镜、音效、BGM），公用品打标签入库。

### 4. 剪辑与合成：AI 出零件，剪辑出成品

生成的片段只是零件，成片靠剪辑：

- **粗剪**：按分镜表顺序把片段排上时间线，先不管节奏；
- **补信息**：字幕（技术类视频必须有，很多人静音看）、必要的图表帧——逻辑图/代码展示用静态图或录屏，别指望 AI 生成清晰代码画面；
- **节奏**：删掉每个镜头的头尾各 0.5 秒（生成模型的起幅收幅最水），单镜控制在 2-4 秒；
- **声音是另一半**：BGM 统一压底，转场音效点一下，配音（自己录或 TTS）对齐字幕；
- **统一调色和字体**：所有 AI 片段过同一个调色预设，字幕用固定字体模板，掩盖素材来源的不一致。

工具选择务实即可：剪映/CapCut 做字幕和粗剪效率最高，DaVinci 做调色，别在工具上折腾超过内容本身。

### 5. 成本控制：把钱花在刀刃上

- **批量在便宜环节试错**：构图、配色、提示词在生图阶段（几厘钱一张）调到位，贵的视频生成只跑"已确认的方案"；
- **限镜头数**：一条 60 秒视频通常 15-20 镜足够，先问"这镜能不能砍"；
- **失败快停**：同一镜头 3 次生成都不对，就改分镜换手法，不在第 4 次上继续烧；
- **记账**：meta.md 里记每次生成的秒数 × 单价，跑两周就知道哪种镜头最费钱，针对性优化；
- **优先用订阅额度**：固定产出量的情况下订阅通常比按次 API 便宜，先算自己的月用量。

## 关键要点

- 脚本先行：先写完文案，再按分镜表逐镜生成；一镜一意，标记可替代镜头；
- 默认走"文生图关键帧 → 图生视频"，文生视频只用于氛围空镜；风格问题在关键帧阶段解决；
- 素材从第一天就按"项目目录 + 镜号命名 + meta 记录"管理，废片进 _trash；
- 剪辑才是成品：删头尾、上字幕、统一调色字体，声音和画面同等重要；
- 成本三板斧：便宜环节试错、镜头能砍就砍、失败三次就换方案，并记账复盘。

## 小结

AI 生视频不是"输入一句话出来一部片"，而是一条工程化的小流水线：分镜表定方向，关键帧控质量，目录和命名管效率，剪辑出成片，记账控成本。把这五个环节跑顺，一个人就能稳定产出可用的短视频——这和写软件一样，靠的是流程，不是灵感。

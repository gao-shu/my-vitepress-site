# AI 编程助手在项目中的落地

## 背景与问题

AI 编程助手（Cursor、Claude Code、Copilot 等）现在几乎是标配，但用得好不好差别巨大。常见两种极端：一种是只把它当高级补全，写个正则、改个拼写；另一种是全盘信任，让模型大刀阔斧改代码，review 不过来就合进去，埋下隐患。

我们日常面对的其实分两类项目，诉求完全不同：

- **老项目**（CRM/ERP/MES 这类跑了多年的系统）：技术栈老、业务规则藏在代码里、没人敢大改。这里 AI 的价值是**帮你理解和局部修改**，而不是重构；
- **新项目**：从零起步或早期迭代，AI 可以承担更多生成工作，但架构决策仍然要人来定。

落地的核心问题不是"模型会不会写代码"，而是：**怎么让模型在正确的上下文里干活，以及怎么保证它的输出不越过安全边界**。

## 方案设计

我们的用法归纳成三层：

1. **上下文管理**：模型的产出质量上限由上下文决定。项目级规则文件（Cursor 的 `.cursor/rules`、Claude 的 `CLAUDE.md`）写清楚技术栈、目录约定、代码风格、禁用写法——这些内容每个会话自动注入，避免每次重复交代；
2. **分工明确**：AI 负责样板代码、单测、CRUD、翻译转换、解释旧代码；人负责架构设计、事务与并发边界、安全相关代码的最终把关；
3. **流程嵌入**：把 AI 接进日常工作流——需求拆解、实现、Code Review、文档，而不是游离在流程外随手用。

老项目和新项目的策略差异要明确：

| 维度 | 老项目 | 新项目 |
|------|--------|--------|
| 打开方式 | 先让 AI 解释代码、梳理调用链，再小步修改 | 可以让 AI 起脚手架、生成模块 |
| 改动范围 | 单一职责、限定文件，改完必跑回归 | 允许跨文件生成，但仍按模块提交 |
| 架构决策 | 人定，AI 只做执行 | 人审，AI 可出方案供挑选 |

## 关键实现

**1. 项目规则文件示例**

把团队约定固化成规则文件，是投入产出比最高的一件事：

```markdown
# CLAUDE.md / .cursor/rules/global.mdc
- 技术栈：Java 8 + Spring Boot 2.x + MyBatis，不要引入 JDK9+ 语法
- 分层：controller 只做参数校验，业务逻辑在 service，禁止在 controller 写业务
- 数据库：表前缀 t_，所有查询必须走索引，禁止 SELECT *
- 禁止引入新依赖，除非先说明理由并经确认
- 修改代码后必须说明受影响的调用点
```

规则要**短、可执行、带否定句**（"不要做什么"比"要做什么"更防翻车），定期把重复纠正的内容沉淀进去。

**2. 老项目的用法**

- **先理解后动手**：让 AI 读某个模块并输出调用链说明、状态流转图，人核对后再让它做局部修改——理解成本从翻几小时代码降到核对几分钟；
- **改动前先要计划**：要求 AI 先列出改动文件清单和影响面，确认后再生成代码，避免"改一处带崩三处"；
- **补测试锁行为**：对老逻辑先让 AI 补单元测试锁住现有行为，再做重构，测试就是安全网。

**3. Code Review 协作**

双向使用：AI 生成的 diff 先让 AI 自查一遍（并发问题、空指针、事务边界、异常吞没），再人审；人写的代码也可以让 AI 做第二双眼睛，标注潜在 bug 和不符合规则的地方。但**合入决策永远是人做**——尤其是涉及金额、权限、并发的代码，AI 的"看起来没问题"不算数。

**4. 安全边界**

- **代码外发**：涉密项目注意代码是否经过外网 API，敏感模块（财务、加密、核心算法）在隔离环境处理或干脆不用 AI；
- **凭据与敏感信息**：任何情况下不让模型生成/传播密钥，已泄露的凭据按安全事故处理轮换；
- **依赖与命令**：AI 建议安装新依赖、执行 shell 命令时，人工确认，防止引入供应链风险或误执行破坏性命令；
- **权限收敛**：AI 代理的写操作限定在工作区，禁止直接操作生产库和线上环境。

## 落地效果

例如一个老 MES 项目上的典型使用节奏：

- 需求来了，先让 AI 解释相关模块并列出改动计划，核对影响面后再生成代码；
- AI 产出的 diff 经过自查 + 人工 review 两道，测试通过才合入；新功能模块由 AI 起 70% 的样板代码，人补齐业务规则和边界处理；
- 规则文件沉淀了团队常见纠正项之后，来回返工的次数明显减少。

以上是示意——实际提效因项目复杂度和领域差异很大，建议团队先在非核心模块试用一两周，统计"AI 产出被采纳的比例"和"返工次数"，再推广到核心模块。

## 小结

AI 编程助手的落地要点：**用规则文件管住上下文，老项目以理解和局部修改为主、新项目再放开生成，人机分工卡在"AI 生成、AI 自查、人工把关"这条线上，安全边界（外发、凭据、依赖、权限）提前划清**。工具的效率上限取决于流程是否严谨，而不是模型有多强。

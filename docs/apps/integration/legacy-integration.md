# 老系统集成改造

## 背景与问题

做集成十有八九会撞上老系统：跑了十年的 ERP、买来的财务软件、当年某个供应商交付后就找不到人的程序。它们的共同特点是——**没有接口，没人懂内部实现，还不能停**。

可选的对接手段各有代价：

- **库表直连**：直接读写它的数据库。见效最快，但绕过了它的业务校验，写进去的数据它不一定认，还可能被它的事务回滚掉；表结构没文档，字段含义靠猜；
- **消息队列**：老系统旁路一个程序监听库表/WMQ，往队列发。解耦了，但老系统本身还是不产生事件，仍要靠轮询或改造；
- **补接口**：在老系统上包一层 API 或改代码。最干净，但可能没源码、不敢动、供应商失联;
- **停机换新**：理想解，业务等不起。

真实项目里很少二选一，通常是**组合拳 + 分阶段**：先用侵入最小的手段让业务跑起来，再逐步把直连换成正规接口。核心思路是**防腐**——把老系统的脏细节挡在适配层之内，新系统只面对干净的接口。

## 方案设计

**1. 对接手段选型**（按侵入度从低到高）：

| 手段 | 侵入度 | 适用 | 主要风险 |
|------|--------|------|----------|
| 只读库表 | 低 | 报表、数据抽取 | 读到脏数据/半提交数据 |
| 读写库表 + 视图 | 中 | 必须回写且无他法 | 绕过业务校验、锁冲突 |
| 旁路适配程序 + MQ | 中 | 事件化对接 | 轮询延迟、仍依赖表结构 |
| 反向代理/网关包接口 | 中 | 有 HTTP 能力但无文档 | 只能包住已有的能力 |
| 源码补接口/二次开发 | 高 | 有源码、有窗口 | 回归风险，需完整测试 |

**2. 防腐层（Anti-Corruption Layer）**：新系统与老系统之间强制加一层适配——

```
新系统 ──干净接口──▶ 防腐层(适配/翻译/校验) ──脏手段──▶ 老系统
```

防腐层负责：字段映射与单位换算、状态码翻译、老系统的怪异数据格式清洗、超时重试、以及把老系统的错误翻译成标准错误码。**老系统的表名、字段名、状态值只允许出现在防腐层里**，一句都不许渗进新系统的领域代码。

**3. 灰度切换**：不敢一把切换，就双跑 + 逐步切流——

- 阶段一：新系统只读老数据做校验，不影响业务；
- 阶段二：**双写**（写新也写老），比对两边结果，观察差异；
- 阶段三：按流量灰度（如按单据类型/客户/10% 起步），核心路径先读新系统、失败自动回落老系统；
- 阶段四：老链路降为只读兜底，稳定一个周期后下线。

每阶段都有明确的**回退开关**，出问题一键切回老链路。

## 关键实现

**1. 只读直连的保护**——读老库也要克制：

- 用**只读账号**连接，权限只给 `SELECT`，杜绝误写；
- 大表查询强制分页 + 时间窗，避开业务高峰，设置独立数据源和低优先级连接池；
- 对半提交数据，用事务隔离或按「已提交标记字段」过滤，不读中间状态。

**2. 回写老库的谨慎姿势**（实在没有别的手段时）：

```java
// 只写老系统“认”的字段组合，且写在它自己的事务约定里
// 1) 只 UPDATE 它允许外部改的状态字段，不碰金额等受控字段
// 2) 写后回读校验：确认它下次批处理真的消费了这条数据
// 3) 关键单据加“外部写入标记”，避免与它的定时任务冲突/重复处理
```

写完必须**回读确认**，因为老系统可能有自己的校验任务会把「不合法」的数据改回去或作废。

**3. 旁路监听 + MQ**：老库加一个 `update_time` 或触发器不可行时，用**定时轮询水位表**（同增量同步的做法）把变更搬进 MQ，新系统消费。轮询间隔按业务容忍度定，水位 checkpoint 落库，失败不前移。这样老系统零改造，新系统拿到的却是标准事件流——本质上是把「无接口」在现场改造成「有接口」。

**4. 灰度开关与比对**：切流由配置中心开关控制（按客户/单据类型维度），双写阶段跑**每日比对任务**，比对新老两边的单据状态与关键字段，差异自动出报表。回退就是把开关拨回去，不发版。

**5. 防腐层代码形态**：一个独立模块/服务，定义干净的领域接口，内部实现全是老系统适配（SQL、私有协议、报文解析）。单元测试只针对翻译规则；老系统侧的联调用**录制回放的真实数据样本**做回归，防它悄悄变格式。

## 落地效果（示意）

- 老系统零改造的情况下，新系统通过旁路适配 + MQ 拿到了标准事件流，项目不被「供应商失联」卡死；
- 防腐层把老系统的字段怪癖和状态码全部挡在一层之内，新系统领域代码不含一个老库字段名，后续替换老系统时只动适配层；
- 灰度双跑 + 比对阶段提前暴露了若干字段映射差异，正式切流时差异已在测试期修完；回退开关演练可用，切换窗口无停机。

（以上为方案效果示意，非生产统计数据。）

## 小结

老系统集成的现实解不是「推倒重来」，而是：**用侵入最小的手段先打通（只读直连 → 旁路 MQ → 补接口），用防腐层把脏细节圈死在一层之内，用双跑比对 + 灰度切流 + 回退开关把切换风险拆成可承受的小步**。判断做没做好，就看两条：老系统的字段名有没有泄漏进新系统，出问题能不能一秒切回去。

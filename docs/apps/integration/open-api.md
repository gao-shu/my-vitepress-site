# 对外 API 设计与开放平台

## 背景与问题

给第三方开 API，和内部接口完全是两回事。内部接口可以口头约定、跟着发版一起改；对外接口一旦发布，就会有几十个你没见过的团队在调，改错了人家的生产直接挂。

常见踩过的坑：

- **接口规范不统一**：有的接口返回 `{"code":0}`，有的返回 `{"success":true}`，第三方对接时骂娘；
- **鉴权各自为政**：一个系统一套签名算法，甚至明文 AppKey 满天飞；
- **没有限流**：某个客户写了个死循环，把网关打满，所有客户一起遭殃；
- **没有版本管理**：字段说加就加、说删就删，老客户升级要挨个打电话通知；
- **文档靠嘴**：联调时全靠拉群问，问一次答一次，人一走就没人答了。

开放平台本质上是把「接口」当产品来做：规范、鉴权、配额、版本、文档，缺一个都会在客户变多之后爆出来。

## 方案设计

整体分四层：

1. **接入层（网关）**：统一鉴权、限流、日志、路由，业务代码不写这些；
2. **接口层**：统一响应结构、统一错误码、统一入参校验；
3. **能力层**：真正的业务逻辑，只关心业务，不关心谁在调；
4. **运营层**：开发者注册、AppKey 发放、配额管理、文档门户。

关键决策：

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 风格 | REST + JSON | 第三方最容易接，工具链最全 |
| 鉴权 | AppId + 签名 为主，OAuth2 为辅 | 服务间对接用签名省事；需要用户授权时才上 OAuth |
| 限流 | 网关层令牌桶，按 AppKey 维度 | 业务代码不掺和，配置可热更新 |
| 版本 | URL 路径版本 `/v1/`，只增不改 | 老版本保底可用，新能力走新版本 |
| 文档 | OpenAPI 3.0 生成 + 联调沙箱 | 文档即代码，接口变了文档自动跟着变 |

## 关键实现

**1. 统一响应结构**——所有对外接口返回同构数据，错误码全局编号：

```json
{
  "code": 0,
  "message": "success",
  "requestId": "req_8f3a2c",
  "data": { }
}
```

`code != 0` 一律是业务/系统错误，`requestId` 打进日志，客户报障时报这个 ID，一分钟能定位到调用记录。

**2. 签名鉴权（AppId + HMAC）**——核心是「参数按序拼接 + 时间戳防重放」：

```java
String raw = appId + "\n" + timestamp + "\n" + sortedParams + "\n" + body;
String sign = Hex(HmacSHA256(raw, appSecret));
// 服务端校验：appId 存在 && |now - timestamp| <= 5min && sign 一致
```

时间戳窗口 5 分钟，配合 nonce（随机串）存 Redis 可进一步挡重放。**AppSecret 永远不出服务端**，只给签名用，不进 URL、不进日志。

**3. 限流与配额**：两套东西别混——

- **限流**：瞬时速率控制（如 100 QPS），超了直接返回 `429` + `Retry-After`，令牌桶在网关做；
- **配额**：周期总量控制（如每日 100 万次），按自然日计数，Redis `INCR` + 过期即可，快到阈值时提前提醒客户。

**4. 版本管理**：`/v1/orders` 与 `/v2/orders` 可以同时在线。规则很简单：**老版本只修 bug，不加不删字段；破坏性变更必须开新版本**；废弃走 `Deprecation` + `Sunset` 响应头，给足迁移期再下线。

**5. 文档与联调**：接口定义用 OpenAPI 注解写在代码里，构建时生成文档站；再配一个**沙箱环境**（mock 数据 + 自助领测试 AppKey），客户不找人就能跑通第一个请求。

## 落地效果（示意）

- 接入一个新客户的周期，从「拉群、发文档、来回问」缩短到自助注册 + 沙箱自测，人肉答疑量明显下降；
- 某客户程序异常打满限流阈值时，只有该 AppKey 被限，其他客户无感知——这是限流按 AppKey 隔离的直接收益；
- 老版本 `/v1` 与新版本 `/v2` 并行期间，存量客户零改造运行，下线按 Sunset 时间表推进。

（以上为方案效果示意，非生产统计数据。）

## 小结

对外 API 的工程量，一半在「业务接口」之外：统一规范让客户好接，签名 + 时间戳让调用可追责，限流配额让故障不扩散，版本纪律让老客户不被绑架，文档沙箱让你不用当人肉客服。这五件事在客户只有 1 个时看着多余，到第 10 个客户时就是救命的。

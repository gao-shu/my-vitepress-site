# ERP 流程与单据设计

ERP 的骨架是单据：采购单、入库单、销售出库、收款单。单据之间靠审核流串起来，靠状态机保证不乱。这块设计错了，后面库存对不上、报表对不上，全是烂账。这篇整理单据与流程设计的关键点。

## 背景与问题

- 单据状态散落在代码各处：`status=1` 是草稿还是已审核，靠口口相传，改一个状态牵一发动全身。
- 审核走过的人多：发起人、部门经理、财务，金额不同走不同分支，硬编码 if 越堆越多。
- 库存与单据联动容易重复记账：网络重试、页面双击，同一张单据把库存加了两次。
- 单据做错了要改不能删：直接 delete 单据，库存和账全乱，审计也过不了。
- 报表口径不统一：销售日报按创建时间、财务按审核时间，两张表数字对不上，开会先吵架。

## 方案设计

### 单据状态机

每类单据定义显式状态机，状态与允许的流转写成表，不允许的状态流转直接拒绝：

```
草稿 →(提交) 待审 →(通过) 已审核 →(记账) 已记账 →(完成) 已完成
  ↑        ↓(驳回)      ↓(作废)
 草稿     草稿         已作废
```

- 状态字段只存枚举，不允许业务代码直接赋值，必须走 `transition(from, event)` 方法。
- 非法流转抛业务异常并记录日志——这是发现「代码里有人偷改状态」的最好手段。
- 状态变更与操作日志同事务，谁在什么时候把单据从什么改到什么，全部可查。

### 审核流

- 流程定义（节点、审批人、条件）配置化，常用用自研轻量审批或 Flowable 类引擎。
- 审批条件基于单据头字段与明细汇总：金额、部门、客户等级。
- 会签、或签、加签、退回重审是标配，别等客户提出来才补。
- 审批动作幂等：同一个审批请求重复提交，只生效一次。

### 库存与单据联动

| 规则 | 做法 |
|------|------|
| 记账时机 | 审核通过才影响库存（或明确「保存即占库」的产品约定） |
| 联动方式 | 单据 → 库存流水 → 汇总，流水是唯一事实来源 |
| 并发 | 扣减用乐观锁或 `update ... where qty >= n`，超卖直接失败 |
| 可追溯 | 每笔库存变化必须能回溯到源单据号 |

### 幂等与冲红

- 幂等：单据号生成一次（雪花/号段锁），接口带幂等键，重复请求返回首次结果。
- 冲红不删除：审核后的单据要改，做一张红字单据冲销原单，原单标记「已冲红」。
- 删除只允许草稿态；已审核的一律走作废/冲红，保留审计链。

### 报表口径统一

- 时间口径统一：业务单据默认按**审核时间**入账期，报表配置里写死并公示。
- 数据源统一：报表从流水/汇总表读，不直接扫明细单据表现场算。
- 口径写进文档：每个指标定义「算什么单据、什么状态、什么时间字段」，争议先查文档。

## 关键实现

状态机流转（示意）：

```java
public void transition(String billNo, BillEvent event, User operator) {
    Bill bill = lockForUpdate(billNo);
    BillStatus next = stateMachine.next(bill.getStatus(), event); // 非法则抛异常
    bill.setStatus(next);
    billLogService.log(billNo, bill.getStatus(), next, operator); // 同事务
}
```

要点：

- 记账（影响库存）与状态流转放同一事务，先改库存后改状态或反之都会出现中间态，必须一起提交。
- 库存流水表带 `bill_no + biz_type` 唯一索引，从数据库层面挡住重复记账。
- 幂等键可用「单据号 + 操作类型」做唯一约束，插入冲突即视为已处理。
- 红字单据与原单通过 `source_bill_no` 关联，报表里红蓝相抵后才是真实数量。
- 审批回调（外部 IM 待办、超时自动通过）也走同一个 `transition`，不另开后门。

## 落地效果（示意）

以下为模式效果示意，非生产数据：

- 状态全部收敛到状态机后，「改状态」的线上问题基本消失，非法流转在测试期就被拦住。
- 库存流水可回溯到每张单据，对账从「翻代码查日志」变成「查流水表」。
- 重复提交、双击记账不再产生重复库存，唯一索引兜底。
- 报表口径写进文档后，销售与财务对数的会议明显变短。

## 小结

单据设计的三个不能省：显式状态机（不许偷改状态）、流水化联动（库存只认流水）、冲红不删除（审计链完整）。审核流和报表口径看着是功能，实际是同一套思路——把规则从代码里搬到可查、可配、可追溯的地方。

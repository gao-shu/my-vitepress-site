# 设备监控与告警

设备监控的常见结局：接了几百个点，阈值随手拍脑袋写死，报警一响就是刷屏，两个月后所有人把通知静音，系统形同虚设。这篇讲怎么把指标采集、告警分级、看板和故障复盘做成一套能长期用的监控，而不是报警轰炸机。

## 背景与问题

- 点位接了不少，但**看不过来**：大屏一开全是数字，哪台设备有问题、问题多严重，要靠人盯。
- 阈值拍脑袋：统一设「温度 > 80 报警」，夏天天天误报，冬天从不报警，班长直接关通知。
- 告警不分级：设备停机和传感器断线一个待遇，都打电话叫人，重要告警被淹没。
- 出了故障复不了盘：只知道「昨晚停过」，当时哪些指标异常、哪条报警先来、谁处理的，查不到。
- 看板与告警两张皮：看板是看板、告警是告警，数据口径不一致，讨论时先对数。

## 方案设计

### 指标采集与阈值

- 指标分层：**设备状态**（运行/停机/故障，开关量）、**工艺参数**（温度、压力、转速，模拟量）、**运行统计**（运行时长、启停次数、产量）。
- 阈值三种配法，缺一不可：
  1. 固定阈值：厂家说明书给的上下限，硬边界。
  2. 动态阈值：按班次/季节/工艺段的历史均值 ± N 倍标准差，减少误报。
  3. 持续条件：`温度 > 80 持续 30s` 才报，过滤瞬时抖动。
- 阈值按设备型号 + 工艺段配置化，存库可热更新，**不要写死在代码里**。
- 采样与评估分离：采集按点位频率进时序库，评估器定时（如 5s）跑一遍规则，避免每个采样点都触发判断。

### 告警分级与通知

| 级别 | 含义 | 通知方式 | 示例 |
|------|------|----------|------|
| P1 紧急 | 设备停机/安全联锁 | 电话/短信 + IM @值班 | 主轴过载停机 |
| P2 严重 | 持续超限，不处理会停机 | IM @设备员 | 温度持续超上限 |
| P3 一般 | 需要关注 | IM 群消息 | 传感器断线 |
| P4 提示 | 信息类 | 只入看板 | 到保养周期 |

- 告警收敛：同一设备同一指标 N 分钟内重复触发合并为一条，计数累加，不重复轰炸。
- 认领与升级：告警超时未认领自动升级到上一级（P2 超 15 分钟无人接 → 升 P1 通知班长）。
- 每条告警有状态机：`触发 → 认领 → 处理中 → 已恢复/已关闭`，谁在什么时候关的要留痕。

### 看板展示

- 三层看板：**车间大屏**（红黄绿状态灯 + 关键告警列表）、**班长屏**（本区域设备状态 + 趋势曲线）、**详情页**（单设备全指标 + 历史告警）。
- 颜色只服务分级：红 = P1、黄 = P2/P3、绿 = 正常，别把装饰色混进来。
- 看板与告警读同一份数据口径（同一时序库 + 同一聚合服务），不各算各的。

### 历史回溯与故障复盘

- 时序数据保留分层：原始采样保留 7~30 天，5 分钟聚合保留 1 年，班次/日报聚合长期保留。
- 告警事件表关联当时的指标快照（触发时刻前后 N 分钟的曲线切片），复盘时不用再去猜「当时温度多少」。
- 复盘产出：故障时间线（首告警 → 认领 → 恢复）、根因分类、阈值/流程改进项——**复盘的输出是改阈值和改流程，不是写报告**。

## 关键实现

告警规则评估与收敛（示意）：

```java
// 定时评估，不用每个采样点都判断
public void evaluate(Device dev, Point p, List<Sample> window) {
    Rule rule = ruleCache.get(dev.model(), p.code());      // 型号 + 点位 → 规则
    if (!rule.hit(window)) return;                          // 固定/动态/持续条件
    AlarmKey key = new AlarmKey(dev.id(), p.code(), rule.id());
    if (alarmSuppressor.merged(key, Duration.ofMinutes(5))) // 5 分钟内合并计数
        return;
    Alarm a = alarmService.create(key, rule.level(), window.latest());
    notifyRouter.send(a);                                   // 按级别路由通知
    snapshotService.capture(a, window);                     // 存触发前后曲线切片
}
```

要点：

- 动态阈值用滑动窗口统计（近 7 天同时段均值与标准差），窗口数据从时序库聚合，不常驻内存全量。
- 通知路由独立成服务：级别 → 通道 → 人员/班组排班表，换通知方式不动告警逻辑。
- 告警状态机与操作日志同事务，杜绝「群里说一句就算处理完了」。
- 看板接口带降级：时序库慢查询时先出状态灯（状态数据独立缓存），曲线区域显示「加载中」，大屏不能白屏。

## 落地效果（示意）

以下为模式效果示意，非生产数据：

- 阈值配置化 + 持续条件上线后，无效报警大幅下降，班长不再静音通知。
- 分级通知推行后，电话只留给 P1 停机类，P3 走群消息，重要告警不再被淹没。
- 告警带曲线切片，复盘从「翻半天历史曲线」变成点开告警直接看现场。
- 复盘改进项回灌到阈值配置，同一类误报第二次出现的概率明显降低。

## 小结

设备监控的价值不在「接了多少点」，在于**告警准确、有人接、能复盘**：阈值配置化并支持动态与持续条件、四级告警配收敛与升级、看板与告警同口径、告警带上下文快照支撑复盘。监控系统的成熟标志是报警变少而不是变多——剩下的每一条，都值得有人去看。

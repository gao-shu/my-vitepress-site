# 轻量 MES 落地实践

MES 这个词被厂商讲得很重：排产、APS、WIP、追溯、看板，一上来几十个模块。真实的小工厂（几十到几百人）要的往往只是四件事：工单发下去、工序报上来、质检记下来、产量能对上。这篇讲怎么用一套轻量 MES 把这四件事跑通，并且交付到现场去。

## 背景与问题

- 生产进度靠微信群和口头问：车间主任下班才知道今天差多少，插单全靠吼。
- 报工靠纸质流转卡：月底统计员录 Excel，错漏改对不上，计件工资扯皮。
- 质检记录散落：巡检表在班长抽屉里，出了客诉找不到当班的检验数据。
- 与 ERP 的边界不清：上了 ERP 又上 MES，两边都管库存、都管工单，数据打架。
- 交付即烂尾：厂商 demo 演示漂亮，现场工位没人愿意用，三个月后系统停摆。

核心矛盾：**管理诉求是「事后统计」，现场诉求是「少填表」**。两者对不上，系统就活不下来。

## 方案设计

### 核心模块（只做四个）

| 模块 | 职责 | 关键点 |
|------|------|--------|
| 工单 | 下达、拆分、派工、关闭 | 工单头 + 工序行，状态机管理 |
| 工序 | 路由与流转 | 每道工序绑定工位/设备/人员 |
| 报工 | 完工回报 | 扫码/工位机上报，防重复、可离线 |
| 质检 | 首检/巡检/终检 | 绑定工序，不合格走处置单 |

排产先不做 APS，用工单优先级 + 人工拖拽的简单甘特就够；设备采集另开话题，先保证人报的数据准。

### 与 ERP 的边界

一句话原则：**ERP 管「账」，MES 管「事」**。

- 物料主数据、BOM、库存账、成本：ERP 是源头，MES 只读不写。
- 工单的物料领用/完工入库：走 ERP 接口过账，MES 只发事件不记账。
- 生产过程数据（报工明细、质检记录、在制状态）：MES 自己存，ERP 不需要明细。
- 边界争议的判据：**这个数据会不会进财务报表**。会，归 ERP；不会，归 MES。

### 现场交付与联调

- 联调顺序：先单工位跑通（扫码 → 报工 → 入库），再扩到整线，最后并行双轨（纸质 + 系统一周），数据对上了才切。
- 五端协同（工位机/班组长/仓管/质检/管理端）不要一次全上，按角色一周一个端推。
- 现场网络、扫码枪型号、工位机分辨率，都要在试点线实测，不能拿办公室环境想当然。

### 从小切口起步

选一条**痛点最明显、班组长最支持**的线，只上「工单 + 报工」两个模块，两周内让主任看到当天产量是实时的。有了信任再加质检、再扩线。切口越小，翻车越少。

## 关键实现

工单状态机（不许代码直接改状态）：

```java
public enum WoStatus { CREATED, RELEASED, RUNNING, SUSPENDED, DONE, CLOSED }

public void transition(String woNo, WoEvent event, User op) {
    Wo wo = lockForUpdate(woNo);
    WoStatus next = WoStateMachine.next(wo.getStatus(), event); // 非法流转抛异常
    wo.setStatus(next);
    woLogService.log(woNo, wo.getStatus(), next, op);           // 同事务
}
```

报工接口的防重与幂等：

- 工位机生成 `reportNo = 工位号 + 工序 + 时间戳`，服务端唯一索引兜底，双击、重试都不会记两次。
- 报工与工序流转（上道完成、下道开工）放同一事务，避免「产量记了、工序还卡着」。
- 离线补报：工位机本地 SQLite 排队，恢复网络后按 `reportNo` 幂等补发，服务端返回首次结果。

工序流转与库存的关系只留一条通路：完工报工触发 ERP 的完工入库接口，失败进重试队列，**MES 自己绝不直接写 ERP 的库存表**。

## 落地效果（示意）

以下为模式效果示意，非生产数据：

- 试点线先上工单 + 报工，班组长当天下班就能看到实时产量，第二周质检模块才上。
- 纸质流转卡与系统双轨一周，产量差异收敛到个位数后停用纸卡。
- 计件工资从「月底录 Excel」变成「报工明细直接汇总」，扯皮点减少。
- ERP 边界定清后，库存对不上的问题归因不再互相甩锅，各查各的流水。

## 小结

轻量 MES 的落地公式：**四个核心模块（工单/工序/报工/质检）+ 一条清晰边界（ERP 管账、MES 管事）+ 一个最小切口（先跑通一条线）**。交付比开发难，双轨并行、数据对账、按角色逐端上线，比一次性切换稳得多。系统能不能活，取决于主任下班时看到的数字准不准，不取决于模块数量。

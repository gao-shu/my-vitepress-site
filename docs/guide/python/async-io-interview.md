## 口述参考

### 1）选型表

| 场景 | 更合适 | 原因 |
|------|--------|------|
| 等网络/磁盘 | 多线程或 asyncio | IO 等待可重叠 |
| 重 CPU | 多进程 | 绕过 GIL 吃多核 |
| 大量并发连接 | asyncio | 单线程协程，注意别阻塞 |
| 简单脚本偶尔并行 | concurrent.futures | API 简单 |

注意：asyncio 里调用同步阻塞（重计算、同步 requests）会堵整个循环——要用线程池包一层或换异步库。

### 2）HTTP 调用清单

- **timeout**（连接 + 读取）必设  
- 状态码与业务 code 分开处理  
- 重试：仅幂等（GET/部分 PUT）；加退避  
- 连接池：`requests.Session` / httpx  
- 密钥：环境变量或密钥管理，不进仓库  
- 日志：打 URL/耗时/状态，脱敏 Token  

调 AI API 同理：超时、重试、限流、费用与失败原因可观测——见 [AI 应用最小链路](/ai/dev/basics/ai-app-min-loop)。

### 3）大文件

逐行 / 分块读；生成器管道；别 `read()` 一次性进内存。  
CSV/日志处理是面试常场景。

### 4）异常与重试

```text
可重试：超时、429、5xx（看业务）
不可盲重试：4xx 参数错误、业务拒绝、非幂等写
```

捕获具体异常；记录上下文；最终失败要有明确返回或告警。

### 5）日志

用 `logging` 模块；级别区分；脚本也要有格式（时间、级别、消息）。  
生产避免 `print` 当日志。

### 6）对比 Java

Java 业务里常用线程池、边界清晰；Python 脚本侧更常「按任务选模型」。  
你可说：主系统 Java；辅助链路 Python，契约用 HTTP/文件/消息对齐。

## 追问预备

- 「GIL 下线程还有用吗？」→ IO 密集有用；CPU 密集有限。  
- 「如何优雅停？」→ 捕获信号、设 stop flag、线程/进程可 join、关闭连接。

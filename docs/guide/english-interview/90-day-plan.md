# 90天英文技术面试计划

目标只有一个：

> **90 天后，能用英语完成一次 30～45 分钟的真实技术面试。**

这不是每天打卡表，也不是英语课程大纲。按三个月能力递进：

```text
第1个月：能讲自己
第2个月：能讲技术
第3个月：能参加面试
```

技术知识本身看就业指南和 [AI → 技术](/ai/dev/)。这里只练：**怎么用英语讲出来。**

---

## 每天怎么练（约 40 分钟）

同时还要找工作、做技术准备、推 AI 项目、建站，所以不按每天 2～3 小时英语学习来设计。

```text
10 分钟  听（例题 / 自己录音 / 面试问题）
15 分钟  开口回答
10 分钟  复盘（卡在哪、哪句说不顺）
5 分钟   记录（答案草稿 / 生词 / 下次改什么）
```

原则：

> **Speaking > Listening > Writing > Grammar**

英文技术面试有两个核心能力：听懂问题和讲清答案。因此训练优先级是先保证能听懂，再保证能开口表达。

Writing 只为准备能说的答案，不把本专题做成英语作文库。

---

## 训练闭环

统一采用：

```text
输入
  ↓
理解
  ↓
开口
  ↓
录音
  ↓
复盘
  ↓
追问
  ↓
再次开口
  ↓
验收
  ↓
沉淀到网站
```

> 本专题不是「看英语资料」，而是训练英文技术沟通。每一个主题都必须经历「看懂 → 开口 → 发现问题 → 修改 → 再说」这个过程。

明确：

- 第一次可以看稿
- 第二次看关键词
- 第三次尽量脱稿
- 最终目标不是背稿，而是能够用自己的话稳定表达

---

## 每次训练怎么做

### 一次训练约 40 分钟

```text
5 分钟   理解问题
10 分钟  看示例 / 准备答案
10 分钟  开口回答
5 分钟   录音复盘
5 分钟   处理追问
5 分钟   修改答案并再次回答
```

> 如果当天状态不好，不要求完成全部 40 分钟。最低标准是完成一次真实开口回答。

> **开口优先，不追求一次说对。**

---

## 答案训练三级法

每一个英文技术问题统一采用：

### Level 1：看稿

完整阅读答案并理解意思。

目标：能把答案完整说出来。

### Level 2：看关键词

只允许看 3～8 个关键词。例如：

```text
Redis
cache
database
performance
expiration
consistency
```

目标：根据关键词自己组织语言。

### Level 3：脱稿

完全不看答案。

目标：像真实面试一样回答，并处理 1～2 个追问。

> Level 3 能稳定完成，才算真正掌握。不是「文章看过」就算完成。

---

## KPI（和目标相关，不是背单词）

> **题目数量只是训练量，不是最终成果。真正目标是：能在没有逐字稿的情况下，用简单英语回答，并能够处理 1～2 轮追问。**

90 天后大致要对齐：

```text
英文自我介绍          3 个版本（30s / 60s / 90s）
英文项目介绍          3 个
Java                  ~40 题（短答能开口）
并发 / JVM            ~20 题
MySQL / Redis / MQ    ~30 题
Spring / 微服务       ~20 题
AI                    ~20 题
Agent                 ~20 题
场景题                ~20 题
完整模拟面试          20 次+
```

**现在不要一次造 150 篇文章。** 题目随训练产生，再挂到网站上。

未来单题统一格式（示意）：

```markdown
# What is Redis?

## Short Answer
...

## Key Points
- ...

## Follow-up
...

## My Answer
...

## Useful Words
- ...
```

答案要短、能说、能记、能展开。不要把中文八股翻译成 500 字英文。

---

## 每周验收（Week 2～12 通用）

每周至少完成：

```text
3～5 个核心问题
+
1 次录音
+
1 次追问训练
+
1 次小型模拟面试
```

每周只记录：

```text
本周能说什么
本周卡在哪里
下周要修什么
```

不要做复杂打卡系统。过不了验收：不增加新内容，继续修当前问题。

## 第1个月：能讲自己

### Week 1 · Self Introduction

训练素材：[Self Introduction](./self-introduction)

完成 30 秒 / 60 秒 / 90 秒三版，覆盖：

```text
工作年限 · 技术背景 · 主要经历
核心技术 · 最近方向 · 当前求职方向
```

原则：简单、自然、能脱稿。不追求高级词汇。

#### Day 1 · 理解自己的英文介绍

目标：不背，先理解自己是谁、做过什么、现在想做什么。

任务：

1. 阅读 60 秒自我介绍
2. 标记不会说的单词和句子
3. 把难说的句子改成自己更容易说的表达
4. 大声读 3 遍

验收：能看着英文稿完整说完 60 秒。

#### Day 2 · 关键词表达

任务：

1. 把 60 秒介绍压缩成 10～15 个关键词
2. 只看关键词回答
3. 连续录音 3 次
4. 记录卡点

重点记录：

```text
A. 单词不会说
B. 句子太长
C. 中文能想到，但英文组织不出来
D. 不知道怎么继续
```

验收：不看完整稿，只看关键词，能够基本完成 60 秒介绍。

#### Day 3 · 完全脱稿

任务：

1. 不看英文稿
2. 不看关键词
3. 连续录音 3 次
4. 每次只修一个问题
5. 第三次重新完整回答

验收：能够在没有稿子的情况下完成基本介绍。

#### Day 4 · 30 / 60 / 90 秒切换

分别练习：

```text
30 秒：快速介绍自己
60 秒：标准介绍
90 秒：需要展开时介绍
```

重点：不是背三篇文章，而是学习控制回答长度。

验收：面试官说 “Could you briefly introduce yourself?” 时能讲 30 秒；正常情况下讲 60 秒；对方感兴趣时可以自然展开到 90 秒。

#### Day 5 · 第一次追问

练习：

```text
What kind of projects have you worked on?
What was your main responsibility?
What technologies did you use?
Why are you moving into AI application development?
What kind of AI applications have you built?
```

每题 20～40 秒。第一次可以看答案，第二次看关键词，第三次脱稿。

#### Day 6 · 小型模拟面试

按照：

```text
Self Introduction
  ↓
Project Experience
  ↓
Main Responsibility
  ↓
Technology Stack
  ↓
Why AI?
```

连续进行 5～10 分钟。不要中途暂停查单词。

遇到不会的地方，必须练习使用：

```text
Let me think about that for a moment.
I'm not sure about the exact implementation, but...
Let me explain it with an example.
I haven't worked with it directly, but...
```

#### Day 7 · 周验收

完成一次完整录音：

```text
30 秒自我介绍
  ↓
60 秒自我介绍
  ↓
1 个项目问题
  ↓
1 个技术问题
  ↓
Why AI?
  ↓
1 个追问
```

验收标准（不是英语是否完美）：

- 能不能听懂问题
- 能不能开口
- 能不能讲完整
- 是否大量依赖逐字稿
- 能否处理至少 1 次追问
- 卡住后能不能继续

如果能够基本完成 → **进入 Week 2。**  
如果不能 → 不增加新内容，继续修当前问题。

### Week 2 · Project Introduction

选 3 个真实项目练同一骨架：

| 项目 | 方向 |
| ---- | ---- |
| A | MES / 工业数字化 |
| B | Java / 企业业务系统 |
| C | AI 应用 / Agent / AI 漫剧平台 |

```text
Background → Responsibility → Architecture → Technology
→ Challenge → Solution → Result
```

不能虚构结果。没有数据就明确说 design / implementation / personal project / prototype / current development。正在开发的不要说成已上线。

周末按「每周验收」执行；过不了不进入 Week 3。

### Week 3 · Workplace English

能用英语描述一天的开发工作，例如：

```text
What did you work on yesterday?
What are you working on today?
What problem did you encounter?
How did you find the problem?
How did you solve it?
How did you communicate with your team?
How do you work remotely?
How do you handle a technical disagreement?
```

周末按「每周验收」执行。

### Week 4 · Basic Interview

准备开口答：

```text
Tell me about yourself.
Why are you looking for a new job?
What kind of projects have you worked on?
What technologies are you familiar with?
What was your most difficult technical problem?
What are your strengths?
Why are you interested in this position?
Why do you want to work remotely?
```

周末按「每周验收」执行。月末对照下方 Day 30。

## 第2个月：能讲技术

核心原则：

> **不重新学习技术，只把已有技术转换成英文表达。**

每题目标：基础问题约 30 秒；需要展开时 1～2 分钟。

统一可用四个问题练：

```text
What is it?
Why do we use it?
How does it work?
What problem does it solve?
```

每个问题都走：三级法 + 训练闭环 + 周末验收。

### Week 5 · Java

JVM、HashMap、ArrayList、ConcurrentHashMap、String、equals / hashCode、Exception 等——短答能开口，能跟追问。

### Week 6 · Concurrency + JVM

synchronized、ReentrantLock、volatile、CAS、Thread Pool、CompletableFuture、JVM Memory、GC、OOM。

### Week 7 · Database + Redis + MQ

- **MySQL**：Index、Transaction、Isolation、MVCC、Slow Query、SQL Optimization  
- **Redis**：Cache、Expiration、Persistence、Distributed Lock、Penetration / Breakdown  
- **MQ**：Async、Retry、Duplicate、Message Loss  

### Week 8 · Spring + Distributed Systems

IOC、AOP、Spring Boot、Spring Cloud、Nacos、Gateway、Feign、分布式事务 / 锁、高并发、负载均衡。

重点不是背英文八股，而是用英语解释真实工程问题。例如 *How would you handle high traffic?* 用简单工程语言：

```text
First, I would identify the bottleneck.

If the database is the bottleneck,
I may introduce caching.

If the operation doesn't need to be synchronous,
I can use a message queue.

For high traffic,
I would also consider horizontal scaling.
```

这种风格比复杂英文更符合目标。月末对照下方 Day 60。

## 第3个月：AI + Agent + 真实面试

这是差异化部分。知识本身看 [AI → 技术](/ai/dev/) 和 [Agent 应用](/ai/app/agent/development)；这里只练英文怎么讲。

### Week 9 · AI

LLM、Prompt、Context、Token、Embedding、RAG、Vector Database、Function Calling、Structured Output——用英语解释，不重写知识文。

### Week 10 · Agent

准备能答：

```text
What is an Agent?
What's the difference between an Agent and a chatbot?
How does tool calling work?
How do you manage context?
How do you control Agent execution?
How do you handle Agent failures?
How do you validate Agent results?
How do you prevent infinite loops?
How do you evaluate an Agent?
```

### Week 11 · 自己的项目

**AI 漫剧平台**（结合正在做的产品，不夸大已上线）：

```text
Why did you build it?
What problem does it solve?
What's the architecture?
Where does AI / Agent participate?
How do you manage context / state?
How do you validate the result?
What problems did you encounter?
What would you improve?
```

**MES / 工业**、**Java 企业项目** 同样准备完整英文项目介绍（Background → Result）。

### Week 12 · 模拟面试

不再大量学新知识。按真实流程练 30～45 分钟：

```text
Self Introduction
  → Project
  → Java → Concurrency → Database → Spring → Distributed
  → AI → Agent
  → Scenario Questions
  → Questions for Interviewer
```

对照下方 Day 90。

## 面试生存句（全程都要用）

| 情况 | 句子 |
| ---- | ---- |
| 没听懂 | Sorry, could you repeat the question? |
| 没听清 | Could you clarify what you mean by...? |
| 思考 | Let me think about that for a moment. |
| 不确定 | I'm not sure about the exact implementation, but my understanding is... |
| 没做过 | I haven't worked with it directly, but I've worked with similar technologies. |
| 举例 | Let me explain it with an example. |
| 换说法 | Let me rephrase that. |
| 纠正 | Let me correct that. |

英文面试是技术沟通，不是英语演讲。这些句子是生存能力，不是点缀。

## 网站内容沉淀规则

不要每训练一个问题就机械创建文章。只有当内容经过实际开口训练后，才考虑沉淀。

```text
训练
  ↓
发现问题
  ↓
修改答案
  ↓
再次训练
  ↓
基本稳定
  ↓
沉淀到网站
```

网站优先记录：

- 最终答案
- 关键词
- 高频追问
- 自己真实遇到的卡点
- 修改前后区别
- 模拟面试记录

内容产生节奏（示意，仍以训练为准）：

```text
Week 1   → 英文自我介绍（已挂站，持续改）
Week 2   → MES / 企业 / AI 项目英文介绍
Week 5   → What is HashMap?
Week 7   → How does Redis caching work?
Week 10  → What is an Agent?
Week 11  → Explain my AI drama platform
Week 12  → Mock Interview #01, #02 …
```

> **训练产生内容，而不是为了网站制造内容。**

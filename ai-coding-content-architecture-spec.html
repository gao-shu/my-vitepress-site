AI Coding 内容架构 Spec ​

修改契约。本文件不是文章，也不是下一轮的发挥许可。
依据：docs/ai-coding-content-analysis.md（2026-09-20 只读盘点）+ 本阶段指令。
本阶段不改站点正文、导航、配置、模板。

与上一阶段的冲突，按事实处理，不另起一套：

点盘点本指令本契约
Spec 要不要进导航流程里要有，导航先不加明确不加不加。 写进工作流和新/老项目
Spec 章节有多长不超过四项：目标、改动点、验收、不做十个问题，用不到可省略十问是检查清单，文件只有四个标题。 见第 4 节
单次任务 Context贴进对话、不进仓库Spec 是冻结约定，要留下对话里的那份任务 Context 退役，改成一篇短 Spec。 Context 页不再维护第二份
架构发生在何时现文在写完代码之后做「人工架构判断」开发前要有架构架构挪到开发前。 写完后的核对并进 Review，不保留两个架构阶段

1. 重构目标 ​

把 AI Coding 栏目收成一条可重复的开发流程：

text
需求 → 架构 → Context / Rules → Spec → 开发 → Test → Review → Debug / Regression → 交付
1

Cursor 只是执行工具。栏目不写成 Cursor 教程、Prompt 合集或 Vibe Coding。

成功标准只有三条：

  1. 读者能指出 Spec 在流程里的位置，而不必新开一页。
  2. 同一份约定（接口、验收、不做）不会在聊天里丢。
  3. 落地包仍是唯一文件模板，文章数量不增加。

不做：企业级规格系统、每个阶段一篇、空目录、第二套工单示例。

3. 核心概念边界 ​

六个概念各回答一个问题。不能互相替代。

概念回答留下什么不留下什么
Requirements要解决什么问题？问题、给谁用、怎样算有用表结构、类名、Prompt
Architecture系统准备怎么解决？模块边界、技术栈、有哪些接口/表、状态机这种系统级约束这一次的字段校验、验收命令
ContextAI 需要知道这个项目现在是什么？仓库里已成立的事实：00-overview、01-modules、99-gotchas这一次要改什么
RulesAI 在这个项目里必须遵守什么？.cursor/rules/，所有任务都适用某一个功能的验收
Spec这一次要实现什么，做到什么程度算完成？一篇短文件，确认后才许改代码项目永久说明、Rules 正文
Prompt这一轮具体如何向 AI 下达任务？对话。用完可扔不能代替 Spec

另外两个不是开发产物：

  • Agent = 执行角色 / 工作方式。技术说明留在「技术 → Agent」，产品说明留在「Agent 应用」。AI Coding 不解释 Agent 是什么。
  • Skills = 可复用能力，跟人走，不进客户仓库。不代替 Rules，也不代替 Review。

一句话：

Rules 管所有任务。Context 是项目事实。Spec 是当前任务。Prompt 是这一轮怎么问。

AGENTS.md 是给 Agent 的项目卡片（名称、技术栈、禁止项）。它不是 Spec，不是 Rules 全文，也不是 Prompt。

4. Spec 定义 ​

重量上限（下一轮不得突破） ​

  • 一篇 Spec 目标 40 行以内。超过就说明把架构或 Rules 写进来了。
  • 四个标题，不许再加。 禁止出现：风险登记、里程碑、角色矩阵、非功能需求、测试用例表、版本号。
  • 十个问题是动笔前的检查清单，不是十个 ##。
  • 某问用不到：不写空标题，也不写「无」。
  • 新项目第一篇用现有 ticket-admin。不新造例子。
  • 不建 Spec 索引、生成器、状态页。

十问怎么折进四个标题 ​

检查清单写进
1. 背景 / 问题目标（一两句，不单开「背景」）
2. 目标目标
3. 范围范围
7. 涉及模块范围
10. 不做什么范围里的「不做」
4. 输入做到什么
5. 输出做到什么
6. 业务规则 / 约束做到什么（只写这一次的规则）
8. 接口 / 数据变化做到什么；没有就不写
9. 验收标准验收

长期都适用的约束（不改 URL、不加依赖）留在 Rules，不抄进 Spec。系统级状态机若已在架构里定死，Spec 只写「遵守该状态机」，不把架构再讲一遍。

5. 新项目流程 ​

文章：docs/ai/ai-programming/cursor-new-project.md
目标：空仓按流程做出 ticket-admin 的后端三接口。不是 Cursor 按钮教程。

ticket-admin 本身就是一个小系统。架构和第一篇 Spec 都会很短，这是对的。不要为了「像架构」再虚构网关、登录、多模块。

下一轮章节（替换现在的「放文件 → 出方案 → 写代码」）：

节产出写法约束
0. 当天做完什么一个可演示的后端保留现有范围：三接口。前端仍可选，且不进第一篇 Spec
1. 需求三句话：谁、什么问题、怎样算有用不写表和类
2. 架构一个后端模块、一张表、三个 URL、状态机 OPEN→DOING→DONE停在系统边界。字段校验不写在这里
3. Context按落地包填 00-overview.md人写已知事实。不粘贴落地包全文
4. Rules / AGENTS放入 AGENTS.md、00-core.mdc只写「从落地包复制并改名称」。禁止第二套模板
5. Specdocs/ai-context/specs/ticket-apis.md，用第 4 节那个新项目示例接口和「禁止跳步」写在这里。确认后才进入下一节
6. 开发只实现该 SpecPrompt 写「按该文件实现」，链到 Prompt Pattern「实现」，不复制模板
7. 测试用 Spec「验收」里的命令和 curl不另写测试理论。可选链到 Prompt Pattern「测试」
8. Review只审这次 Diff链到 Code Review。不复制 Review Prompt
9. Debug只有失败才做链到 Prompt Pattern「Debug」。不建新页，不做成必写长文
10. 交付对照 Spec 的「不做」打勾保留现有交付清单的作用。不写发布流程

必须删除或改掉的现有写法：

  • 第 1 步那种把包结构、表、接口、状态机塞进一次「方案」回复的 Prompt。拆开：架构一节、Spec 一节。
  • 任何 AGENTS / rules / overview 的全文粘贴。

保留：示例项目名、包名、表名、三个 URL、先不装 Skill、先有约定再改代码。

6. 老项目流程 ​

文章：docs/ai/ai-programming/cursor-legacy-project.md
目标：接手已有仓，安全做完「列表加 status 过滤」这一刀。不重新设计系统。

下一轮章节：

节产出写法约束
0. 禁止事项保持现有禁令不改 URL、不改表、不加依赖、不装 Skill、不编造
1. 扫描三次扫描，一次一个文件保留。 写入 00-overview、01-modules、99-gotchas。标题与落地包锁定，不另起标题
2. 理解这一条调用链01-modules 里只写这次会碰的链写明：这不是系统理解完成，只够这一刀
3. 修正 Context人删掉扫描里的猜测；gotchas 人写Context 来自代码，不是人按理想项目编
4. Rules用扫描到的技术栈填落地包里的 00-core / AGENTS不从零写理想规范。不在本文贴全文
5. Specspecs/list-status-filter.md，用第 4 节老项目示例只描述这一次过滤。禁止写成「重做工单系统」
6. 局部修改按 Spec 改保留现有停手表
7. Test对照 Spec 验收，含「不传参数与改前一致」这就是回归的最小形式
8. Review链到 Code Review不复制 Prompt
9. Regression专查没点名的行为没变不新开文。和 Test 可以同一节，但必须点名「改前行为」
10. 验收保留现有接手清单对照 Spec，不对照一整份理想文档

不新增：全仓文档化、架构重设计、第二套文件模板。

10. 重复内容处理方案 ​

工作流 vs 总览 ​

  • 总览删两段闭环（index.md「什么叫 AI Coding」「AI Coding 工作方式」里的流程块）。
  • 工作流保留唯一阶段表。
  • 「人对需求、架构、质量负责」这句话总览留一句即可，不展开。

Context & Rules vs 00-core.mdc ​

概念页下一轮删除或压成一句的现有块：

  • 「单次任务 Context」整段代码块（约「贴进对话，不进仓库」至示例结束）。同一题改由老项目 Spec 承载。
  • 「Rules 以落地包为准」下面那四条可粘贴规则。改成：边界原文只在落地包 00-core.mdc。
  • 「修改边界」整段默认边界。与 00-core 同义。
  • 「怎么用」里「没有就先写四条」「把 Context + 边界贴进 Prompt」。改成：开任务写 Spec，Prompt 里只给 Spec 路径。

保留：Context 与 Rules 的定义、「给 AI 什么」清单（Diff、报错、调用链）、「Rules 来自真实习惯」。

补三行，不要写成新章节长文：

  • AGENTS = 项目卡片，全文在落地包。
  • Spec = 当前任务，不是本页的内容。
  • 项目事实进 docs/ai-context/，不进对话第二份。

Prompt Pattern vs Code Review ​

  • 删除 Prompt Pattern 第 4 节的可复制 Prompt（现有「请只 Review 下面 Diff」块）。
  • 留下场景一句 + 链到 ai-code-review.md。
  • Code Review 的「可复制：Review Prompt」是唯一全文。文首加一句即可，不改检查维度。

新项目 vs 落地包 ​

  • 落地包提供文件。
  • 新项目只写「复制哪几个、改哪几个名字、何时写 Spec」。
  • 禁止把 AGENTS.md 代码块再贴进新项目。

老项目 vs 落地包 ​

  • 扫描写入的章节标题必须与落地包一致（现状已经如此，保持）。
  • 不复制模板正文。
